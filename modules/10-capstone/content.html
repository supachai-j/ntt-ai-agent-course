📖 Content · Module 10

Capstone Project

รวมทุกอย่างที่เรียนมาจาก module 01–09 เป็นโปรเจกต์ agent เดียวที่ design, build, secure, test และ ship ได้จริง

TL;DR: Capstone ไม่ใช่แบบฝึกหัดเขียน prompt แต่เป็นการเอาความรู้ทั้งคอร์สมารวมร่างเป็น agent ที่ใช้งานจริง — เลือกโจทย์ 1 อันจาก 4 ตัวเลือก (หรือเสนอเอง), ทำตาม checklist ที่โยงกลับทุก module, ประเมินด้วย rubric 4 หมวด, และทำให้เสร็จภายใน 1 sprint (7 วัน) ตาม timeline ที่แนะนำ

ทำไมต้องมี Capstone

ตลอด 9 module ที่ผ่านมา เราเรียนแยกเป็นส่วน ๆ:

  • Agentic loop และ tool use (Module 01 — AI Agents 101)
  • Hermes platform + Claude Code CLI (Module 02 / 03)
  • Engineering workflow + context management (Module 04 / 05)
  • Hooks, permissions, multi-agent orchestration (Module 06 / 07)
  • Governance และ CI/CD automation (Module 08 / 09)
💡 Capstone = การรวมร่าง — โจทย์เดียว แต่ต้องเอาความรู้ทุก module มาใช้จริง ไม่ใช่แค่เขียน prompt แล้วรอผล แต่ต้อง design, build, secure, test และ ship เป็น artifact ที่ demo ได้จริงในเวลาจำกัด

เลือกโจทย์ Capstone

เลือก use case จริงจากงานองค์กรอย่างใดอย่างหนึ่ง (หรือเสนอโจทย์ของทีมตัวเองก็ได้ ถ้าใกล้เคียง scope นี้):

โจทย์รายละเอียด
1. Presale Proposal Generator Agent ที่รับ requirement ลูกค้า + template เดิม แล้ว draft proposal/SOW เบื้องต้น พร้อม citation จาก past project ที่เกี่ยวข้อง
2. Automated PR Reviewer สำหรับทีม รัน Claude Code แบบ headless ใน CI เพื่อ review PR อัตโนมัติ — เช็ค coding standard, security pattern, และ comment กลับใน PR
3. Internal Doc / Runbook Agent Agent ที่ค้นและตอบคำถามจาก internal doc/runbook (RAG หรือ MCP filesystem tool) พร้อมอ้างอิงแหล่งที่มาทุกครั้ง
4. Monitoring / Alert Agent Agent ที่ตรวจ log/metric ผ่าน MCP tool แล้วสรุป incident, เสนอ root cause และแจ้งเตือนทีมผ่าน chat (Slack/Telegram)
💡 เลือกโจทย์ที่ scope เล็กพอทำเสร็จได้จริงใน 1 sprint ดีกว่าเลือกโจทย์ใหญ่แล้ว demo ไม่ได้

Checklist: Solution ต้องมีครบ

ทุก capstone ต้องโยงกลับ concept จาก module 01–09 — นี่คือ checklist ที่ mentor จะเช็ค:

Checklistโยงกลับ Module

ใช้ platform ที่เหมาะสม (Hermes / Claude Code CLI)02 / 03

Deploy/automate ได้จริง ไม่ใช่แค่รันมือ09 — CI/CD & Automation

Rubric การประเมิน

Capstone ถูกให้คะแนนตาม 4 หมวดต่อไปนี้:

หมวดน้ำหนักรายละเอียด
Functionality30%Agent ทำงานได้จริงตาม spec ที่ตั้งไว้ — รันแล้วได้ output ที่ถูกต้อง ไม่ใช่ demo แบบ mock
Safety25%มี hook/permission ครบตาม risk ของ use case — block destructive action, ไม่ leak secret, มี audit trail
Documentation20%มี README.md และ CLAUDE.md ที่อธิบายชัดว่า agent ทำอะไร, setup ยังไง, limitation คืออะไร
Demo25%Demo ได้จริงในเวลาจำกัด (5–10 นาที) — รันคำสั่งจริง ไม่ใช่ slide เล่าเฉย ๆ

Timeline แนะนำ (1 Sprint = 7 วัน)

DayงานOutput

Phase 1–2: Spec + Setup

1. เขียน spec สั้น (1 หน้า) ก่อนเริ่มโค้ด — spec นี้บังคับให้คิดให้จบก่อนแตะโค้ด และเป็นเอกสารที่ mentor/เพื่อนร่วมทีมใช้ทำความเข้าใจโจทย์ได้เร็ว:

## Problem
## Users
## Core loop (observe/plan/act/verify)
## Out of scope

2. Setup project จริง — init repo จริง ไม่ใช่ไฟล์กระจัดกระจายใน local:

mkdir capstone-agent && cd capstone-agent
git init
touch CLAUDE.md README.md
mkdir -p .claude
# settings.json ใส่ permissions/hooks
💡 การเขียน spec.md ก่อนแตะโค้ดคือการนำ discipline จาก Module 04/05 (engineering workflow + context management) มาใช้ตั้งแต่ต้น

Phase 3–4: Build Core Loop + Hook

3. ใช้ Claude Code จริงสร้าง core feature — นี่คือจุดที่เอา Module 03 (Claude Code CLI) มาใช้ตรง ๆ ไม่ใช่เขียนโค้ดมือทั้งหมด:

claude -p "implement the core agentic loop
described in spec.md, write tests" \
  --allowedTools "Edit,Bash(git *),Write"

4. เพิ่ม PreToolUse hook กัน risk — นำ pattern จาก Module 06 (Hooks & Permissions) มาใช้ป้องกัน action อันตรายก่อนที่ agent จะรันจริง:

{
  "hooks": {
    "PreToolUse": [{
      "matcher": "Bash",
      "hooks": [{
        "type": "command",
        "command": "./.claude/hooks/block-danger.sh"
      }]
    }]
  }
}

Phase 5–6: Test + Deploy/Demo

5. Test + capture evidence จริง — evidence ต้องจับต้องได้ ไม่ใช่แค่บอกว่า "test ผ่านแล้ว":

pytest -v | tee test-output.log
git add -A && git commit -m "capstone: tested core loop"

6. เขียน README พร้อม output จริง แล้ว demo — ต้อง copy output จริงจากการรันคำสั่ง ไม่ใช่ตัวอย่างสมมติ:

## Usage
\`\`\`
$ python agent.py "review this PR"
[actual output pasted here]
\`\`\`
⚠️ ห้ามพิมพ์ log มือหรือ mock ผลลัพธ์ — ทุก evidence (test output, README usage) ต้องมาจากการรันจริง

Next Steps หลังคอร์สจบ

  • Resource เพิ่มเติม: Claude Code docs, Anthropic engineering blog, Hermes plugin/skill ecosystem
  • ขอ feedback จากทีม: demo ให้ lead/peer ดู, เก็บ pain point จริงก่อนเอาไป production
  • Scale จาก prototype → งานจริง: ใส่ observability, error handling, cost tracking, และผ่าน governance review (Module 08) ก่อน rollout ให้ทีมอื่นใช้
  • โปรเจกต์นี้ควรอยู่ใน git ของทีม ไม่ใช่แค่ไฟล์ใน local — ทำให้คนอื่นต่อยอดได้
