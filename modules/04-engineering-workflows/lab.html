Lab · Module 04

Engineering Workflows with Claude Code

สร้าง mini-repo จริงที่มี bug ฝังไว้ ใช้ Claude Code print mode หา + แก้ bug, verify ด้วย pytest จริง, ทำ PR review pattern กับ diff จริง แล้วปิดท้ายด้วย TDD mini-exercise ที่คุณเขียน failing test เองแล้วให้ agent implement จนผ่าน

⏱ ~50-70 นาที 🖥 ต้องมี claude, git, python3, tmux ติดตั้งแล้ว 📁 working dir แนะนำ: ~/module04-lab

Prerequisites

  • ผ่าน Module 03 (ติดตั้ง Claude Code, auth สำเร็จ, รู้จัก print mode vs interactive)
  • claude --version รันได้ (แนะนำ v2.x ขึ้นไป)
  • git, python3 (แนะนำ 3.9+), และ tmux ติดตั้งแล้วบนเครื่อง
  • รู้จัก git diff, git branch, git commit พื้นฐาน

Objectives

  • สร้าง feature branch แล้วให้ Claude Code หา + แก้ bug ด้วย print mode พร้อม --allowedTools และ --max-turns
  • Verify การแก้ไขด้วย pytest จริง (exit code 0)
  • ทำ PR review pattern: pipe git diff เข้า claude -p เพื่อ review อัตโนมัติ
  • ฝึกวินัย TDD กับ agent — เขียน failing test เองก่อน แล้วให้ agent implement จนผ่าน (RED-GREEN)
  • เขียน sprint plan ตาม AI-DLC (Ideation/Inception/Construction/Operation) จับคู่กับงานที่เพิ่งทำจริง
  • เข้าใจว่าทำไมต้อง set --max-turns/--allowedTools เสมอในงาน automation

1สร้าง mini-repo พร้อม bug ที่ตั้งใจใส่ไว้

สร้างโปรเจกต์ Python เล็ก ๆ ที่มี pricing utility และ test suite — ฟังก์ชัน apply_discount() จะมี bug ฝังอยู่โดยตั้งใจ

mkdir -p ~/module04-lab/src ~/module04-lab/tests
cd ~/module04-lab

python3 -m venv .venv
.venv/bin/pip install -q --upgrade pip
.venv/bin/pip install -q pytest

สร้าง src/pricing.py:

# src/pricing.py
"""Small pricing utility with a small intentional bug for Module 04 lab."""


def apply_discount(price: float, percent: float) -> float:
    """Apply a percentage discount to a price.

    Bug: uses `price - percent` instead of `price - (price * percent / 100)`.
    """
    return price - percent


def total_with_tax(price: float, tax_rate: float = 0.07) -> float:
    """Return price with tax applied. Correct implementation."""
    return round(price * (1 + tax_rate), 2)

สร้าง tests/test_pricing.py:

# tests/test_pricing.py
from src.pricing import apply_discount, total_with_tax


def test_apply_discount_10_percent():
    assert apply_discount(200, 10) == 180


def test_apply_discount_50_percent():
    assert apply_discount(80, 50) == 40


def test_total_with_tax_default_rate():
    assert total_with_tax(100) == 107.0
cd ~/module04-lab
git init -q
git config user.email "you@example.com"
git config user.name "Your Name"
git add -A
git commit -q -m "Initial pricing module with seeded bug"
git branch -M main
Verify: รัน .venv/bin/python -m pytest tests/ -q — ต้องเห็น 2 failed, 1 passed (exit code 1) เพราะ apply_discount() ยังมี bug อยู่ ถ้าเห็นผลนี้แปลว่า setup ถูกต้อง

2สร้าง feature branch แล้วให้ Claude Code หา + แก้ bug

สร้าง branch แยกสำหรับงานนี้ แล้วสั่ง Claude Code ใน print mode ให้อ่าน test ที่ fail แล้วแก้โค้ดจนผ่าน โดยจำกัดสิทธิ์ให้แก้ได้แค่ไฟล์ source (ห้ามแตะ test)

cd ~/module04-lab
git checkout -b fix/discount-bug

claude -p 'The tests in tests/test_pricing.py are failing for apply_discount() \
  in src/pricing.py. Fix the bug in apply_discount() so all tests pass. \
  Do not modify the test file.' \
  --allowedTools 'Read,Edit' \
  --max-turns 8 \
  --output-format json > /tmp/fix_result.json

python3 -c "import json; d=json.load(open('/tmp/fix_result.json')); print('subtype:', d['subtype']); print(d['result'])"
Verify: subtype ต้องเป็น success และ git diff ต้องแสดงการแก้ไขใน src/pricing.py เท่านั้น — ตรวจด้วย git diff --stat ว่ามีแค่ src/pricing.py เปลี่ยน
ข้อควรระวัง: --allowedTools 'Read,Edit' ไม่รวม Bash ดังนั้น Claude จะแก้ไฟล์ได้แต่รัน pytest เองไม่ได้ — ผลลัพธ์ text มักบอกว่า "ต้องการรัน test เพื่อยืนยัน" นั่นคือพฤติกรรมที่ถูกต้อง เราจะ verify เองในขั้นตอนถัดไป

3Verify การแก้ไขด้วย pytest จริง

อย่า trust ผลลัพธ์จาก agent เฉย ๆ — รัน test เองเพื่อยืนยัน

.venv/bin/python -m pytest tests/ -q
echo "exit code: $?"
Verify: ต้องเห็น 3 passed และ exit code: 0 — ถ้ายัง fail อยู่ อ่าน error แล้วกลับไป iterate รอบสองด้วยคำสั่ง claude -p '...' --continue --max-turns 5 (ดูส่วน Troubleshoot ท้าย lab)

Commit การแก้ไข:

git add -A
git commit -q -m "Fix apply_discount to compute percentage correctly"

4PR Review Pattern: pipe diff เข้า Claude Code

ก่อนเปิด PR จริง ใช้ Claude Code เป็น first-pass reviewer — pipe git diff ระหว่าง branch เข้าไปตรง ๆ

git diff main...fix/discount-bug | claude -p \
  'Review this diff for bugs, security issues, style' \
  --max-turns 3 \
  --output-format json > /tmp/review_result.json

python3 -c "import json; d=json.load(open('/tmp/review_result.json')); print(d['result'])"
Verify: result ต้องมีข้อความ review จริง (ไม่ใช่ null) และควรกล่าวถึงว่า fix ถูกต้อง (subtract percentage แทน flat amount)
ข้อสังเกตจากการทดสอบจริง: --max-turns 1 มักไม่พอสำหรับ review pattern นี้ — Claude มักขอใช้ tool หนึ่งครั้งก่อนตอบ (เช่นอ่าน context เพิ่ม) ทำให้ error error_max_turns ตั้งแต่ turn แรก ให้ตั้งอย่างน้อย --max-turns 2-3 สำหรับ pattern นี้ในทางปฏิบัติ

5Interactive Refactor ผ่าน tmux (human-in-the-loop)

เมื่อ task ต้องการ feedback หลายรอบ ให้ใช้ interactive mode ผ่าน tmux แทน print mode

tmux new-session -d -s lab-refactor -x 140 -y 40 -c ~/module04-lab
tmux send-keys -t lab-refactor 'claude' Enter
sleep 4

รอบแรกที่เข้าไดเรกทอรีนี้ Claude Code จะถาม workspace trust — default ของ dialog คือ "No, exit" ต้องกด Down แล้ว Enter เพื่อเลือก "Yes, I trust this folder":

tmux send-keys -t lab-refactor Down
sleep 0.3
tmux send-keys -t lab-refactor Enter
sleep 3

ส่ง task แรกแล้วตรวจ progress:

tmux send-keys -t lab-refactor \
  'Explain in one sentence what apply_discount does in src/pricing.py, do not edit anything' Enter
sleep 10
tmux capture-pane -t lab-refactor -p -S -40
Verify: capture-pane ต้องแสดงคำอธิบายจาก Claude เกี่ยวกับ apply_discount ในหน้าจอ — ถ้ายังไม่มีคำตอบ ให้ sleep เพิ่มแล้ว capture ใหม่ (ดูวิธี detect ว่า Claude ตอบเสร็จหรือยังในส่วน Troubleshoot ท้าย lab)

ปิดท้าย session เมื่อจบงาน:

tmux send-keys -t lab-refactor '/exit' Enter
sleep 2
tmux kill-session -t lab-refactor

6TDD Mini-Exercise: RED — เขียน failing test เอง

วินัยสำคัญที่สุดของ workflow นี้: เขียน test ก่อนเสมอ ห้ามให้ agent เขียนโค้ด production โดยไม่มี test คุมทิศทาง

สร้าง tests/test_bulk_discount.py — test ฟังก์ชันใหม่ที่ยังไม่มีอยู่จริง:

# tests/test_bulk_discount.py
from src.pricing import apply_bulk_discount


def test_bulk_discount_under_threshold_no_discount():
    # Fewer than 10 units: no bulk discount applies
    assert apply_bulk_discount(unit_price=20, quantity=5) == 100


def test_bulk_discount_at_threshold_applies_10_percent():
    # 10 or more units: 10% off the total
    assert apply_bulk_discount(unit_price=20, quantity=10) == 180


def test_bulk_discount_above_threshold_applies_10_percent():
    assert apply_bulk_discount(unit_price=15, quantity=20) == 270
.venv/bin/python -m pytest tests/test_bulk_discount.py -q
echo "exit code: $?"
Verify (RED): ต้องเห็น ImportError: cannot import name 'apply_bulk_discount' และ exit code: 2 — นี่คือ RED state ที่ถูกต้อง เพราะฟังก์ชันยังไม่มีอยู่จริง

7TDD Mini-Exercise: GREEN — ให้ Claude Code implement จนผ่าน

claude -p 'There is a failing test file tests/test_bulk_discount.py that imports \
  apply_bulk_discount from src/pricing.py, but that function does not exist yet. \
  Read the test file to understand the expected behavior, then implement \
  apply_bulk_discount(unit_price, quantity) in src/pricing.py so that \
  tests/test_bulk_discount.py passes. Do not modify any test file.' \
  --allowedTools 'Read,Edit' \
  --max-turns 8 \
  --output-format json > /tmp/tdd_result.json

python3 -c "import json; d=json.load(open('/tmp/tdd_result.json')); print('subtype:', d['subtype'])"

.venv/bin/python -m pytest tests/test_bulk_discount.py -q
echo "exit code: $?"
Verify (GREEN): ต้องเห็น 3 passed และ exit code: 0 — และ git diff tests/test_bulk_discount.py ต้อง ว่างเปล่า (agent ไม่ได้แก้ test file เลย) ยืนยันด้วย: 
git diff --stat tests/test_bulk_discount.py
# ต้องไม่มี output ใด ๆ ถ้า agent ไม่แตะไฟล์นี้
กฎเหล็ก: ถ้า --allowedTools รวมสิทธิ์แก้ไฟล์ test เข้าไปด้วย agent อาจ "แก้ test ให้ผ่านง่าย ๆ" แทนที่จะแก้ implementation จริง — นี่คือ false green ที่อันตรายมาก ต้องจำกัดสิทธิ์ให้ agent แก้ได้แค่ src/ เท่านั้นในรอบ GREEN

เมื่อผ่านแล้ว commit:

git add -A
git commit -q -m "Add apply_bulk_discount via TDD (test-first)"

8AI-DLC Mini-Exercise: เขียน Sprint Plan ของงานที่เพิ่งทำ

AI-DLC (Ideation → Inception → Construction → Operation) คือ framework ระดับ sprint ที่ครอบ feature loop ที่เพิ่งทำใน step 1-7 ไว้ทั้งหมด — ในขั้นตอนนี้คุณจะเขียน sprint plan แบบย้อนหลังของงาน "เพิ่ม apply_bulk_discount" ที่เพิ่งทำเสร็จ เพื่อฝึกจับคู่งานจริงเข้ากับ 4 phase

สร้าง SPRINT_PLAN.md:

cat > SPRINT_PLAN.md << 'EOF'
# Sprint: Bulk Discount Feature

## Ideation
- User story: "พนักงานขายต้องคำนวณส่วนลดแบบ bulk (10+ ชิ้น ลด 10%) ได้ถูกต้อง"
- Acceptance: unit price x quantity ต่ำกว่า threshold ไม่ลด, ตั้งแต่ threshold ขึ้นไปลด 10%

## Inception
- ไฟล์ที่ต้องแตะ: src/pricing.py (เพิ่มฟังก์ชันใหม่ ไม่แก้ apply_discount เดิม)
- ตัดสินใจ: เขียน test ก่อน (RED) กำหนด contract ให้ agent implement ตาม ไม่ให้ agent
  ออกแบบ signature เอง
- ความเสี่ยง: agent อาจแก้ apply_discount เดิมโดยไม่ตั้งใจ -> จำกัด scope ใน prompt ชัดเจน

## Construction
- Agent (Claude Code, --allowedTools 'Read,Edit') implement apply_bulk_discount
  ตาม test ใน tests/test_bulk_discount.py เท่านั้น
- ไม่มี agent ตัวที่สองแตะไฟล์เดียวกันพร้อมกัน (งานนี้เดี่ยว ไม่ต้อง parallel split)

## Operation
- Verify: pytest tests/test_bulk_discount.py -q -> 3 passed, exit 0
- Verify: git diff --stat tests/test_bulk_discount.py -> ว่างเปล่า (agent ไม่แตะ test)
- ผล: commit "Add apply_bulk_discount via TDD (test-first)"
EOF
Verify: เปิด SPRINT_PLAN.md อ่านทวนแล้วเช็คว่าแต่ละ phase ตรงกับสิ่งที่คุณทำจริงใน step 6-7 หรือไม่ — ถ้า Inception ของคุณไม่ได้ระบุ "ไฟล์ที่ต้องแตะ" ไว้ล่วงหน้าจริง (แค่เขียนย้อนหลังให้ครบฟอร์ม) ให้ลองสมมติ sprint ถัดไปแล้วเขียน Inception ก่อนเริ่ม Construction จริง ๆ ดู
ทำไมต้องทำ Inception ก่อนเขียนโค้ด (ไม่ใช่แค่เขียนพร้อมกัน): กรณีจริงที่พบบ่อย — ถ้าเพิ่ม field ใหม่ลง entity เดิมตรง ๆ โดยไม่ผ่าน Inception อาจพัง logic ที่มีอยู่แล้วโดยไม่รู้ตัว (เช่น entity ใหม่ที่ลืมเพิ่มเข้า index/order list ที่มีอยู่แล้ว จะ "มีอยู่จริงแต่ไม่โผล่ที่ไหนเลย" ใน UI) — Inception คือจุดที่ควร จับ trap แบบนี้ได้ก่อนแตะโค้ดจริง ไม่ใช่หลังจาก debug นานหลายชั่วโมง
Troubleshoot: Agent แก้ผิดจุด หรือ timeout จาก max-turns ไม่พอ

อาการ 1 — subtype: error_max_turns: agent ใช้ turn หมดก่อนตอบเสร็จ (มักเกิดกับ --max-turns 1 ที่ต่ำเกินไป หรือ task ที่ต้องอ่านหลายไฟล์) แก้โดยเพิ่ม --max-turns แล้วรันใหม่ หรือ สาน context เดิมด้วย --continue:

claude -p 'Continue fixing the bug, you ran out of turns last time' \
  --continue --max-turns 10

อาการ 2 — agent แก้ไฟล์ผิด (เช่นแก้ total_with_tax แทนที่จะแก้ apply_discount): เกิดจาก prompt ที่ไม่เจาะจงพอ แก้โดย revert แล้ว prompt ใหม่ให้ระบุชื่อฟังก์ชัน/บรรทัดที่ต้องแก้ชัดเจนขึ้น:

git checkout -- src/pricing.py
claude -p 'In src/pricing.py, the function apply_discount() at line ~4 has a bug: \
  it does `return price - percent` but should compute `price - (price * percent / 100)`. \
  Fix ONLY this function.' \
  --allowedTools 'Read,Edit' --max-turns 5

อาการ 3 — ไม่แน่ใจว่า Claude ตอบเสร็จหรือยังใน tmux session: ตรวจหาบรรทัดที่ขึ้นต้นด้วย ❯ ที่ด้านล่างของ pane (แปลว่า Claude รอ input ใหม่ = ตอบเสร็จแล้ว) เทียบกับบรรทัดที่ขึ้นต้นด้วย ● หรือ Worked for Ns (แปลว่ากำลังทำงานอยู่) — ถ้ายังไม่แน่ใจให้ sleep เพิ่มแล้ว capture-pane ซ้ำ

tmux capture-pane -t lab-refactor -p -S -30 | tail -5

อาการ 4 — --allowedTools บล็อกจนงานไม่คืบ: ถ้าจำกัดสิทธิ์ แน่นเกินไป (เช่นไม่ให้ Bash เลยแต่ task ต้องรัน pytest) agent จะทำได้แค่ แก้ไฟล์แล้วรอ — เพิ่มสิทธิ์เท่าที่จำเป็นจริง เช่น --allowedTools 'Read,Edit,Bash(pytest*)' เพื่อให้ agent รัน test เองได้ในขอบเขตที่ควบคุมได้

สรุป & ต่อยอด

ใน lab นี้คุณได้ฝึก workflow วิศวกรรมหลักที่ใช้ Claude Code เป็น pair-programmer จริง:

  • Feature loop มาตรฐาน — branch → prompt → review diff → verify ด้วย test จริง → commit
  • PR review pattern — pipe diff เข้า claude -p เป็น first-pass reviewer ก่อนส่ง human review
  • Interactive refactor ผ่าน tmux สำหรับงานที่ต้องมี human-in-the-loop หลายรอบ
  • TDD discipline — RED (เขียน test เอง) → GREEN (ให้ agent implement) โดยจำกัดสิทธิ์ ไม่ให้ agent แตะไฟล์ test
  • AI-DLC — เขียน sprint plan ระดับ Ideation/Inception/Construction/Operation ครอบ feature loop ไว้ทั้งหมด และเห็นว่า Inception ที่ดีป้องกัน trap ที่ debug ทีหลังยากกว่ามาก

ต่อยอด: ลองเพิ่ม --max-budget-usd ให้ทุกคำสั่ง claude -p ที่ใช้ในวันนี้ (เช่น --max-budget-usd 0.50) แล้วสังเกตว่า flag นี้เปลี่ยนพฤติกรรมยังไงเมื่อ budget ใกล้หมด — และลองเปลี่ยน --effort ระหว่าง low กับ high ใน step 2 (แก้ bug) เทียบ num_turns/total_cost_usd ที่ได้จาก --output-format json ว่าต่างกันแค่ไหน
