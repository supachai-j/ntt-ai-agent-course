🤖 M01 · Agent ไม่ใช่กล่องดำ

Agent = loop ธรรมดา ห่อด้วยวิศวกรรมหลายชั้น — 4-5 แนวคิดคนละทีม รวมกันใน ~2 ปี

2021-12 · WebGPTโมเดล + browser — เริ่มหาข้อมูลเองได้
2022-01 · Chain-of-Thoughtคิดเป็นขั้นๆ ออกมาเป็นข้อความก่อนตอบ
2022-05 · MRKL Systemsแยกงานให้ module ภายนอกทำแทนโมเดล
2022-10 · ReActต้นตำรับของลูป — "คิด" กับ "ลงมือ" สลับกันในลูปเดียว

ทำไมสำคัญกับ debug

คนที่ debug agent ไม่เป็น ไม่ใช่เพราะไม่เก่ง แต่เพราะไม่มีแบบจำลองในหัวว่าข้างในมีอะไรบ้าง — เมื่อมีแล้ว ปัญหาลึกลับจะกลายเป็นคำถามว่า "ชั้นไหนพัง"

💰 M02 · Context Engineering

📦≠✅บริบทคืองบประมาณ ไม่ใช่ถัง — "ใส่ได้" กับ "ใช้ได้ดี" คนละเรื่อง
Lost in the Middle (2023): context window ใหญ่ไม่ยกเลิกวินัยนี้ แค่ทำให้ค่าเสียหายมาช้าลง

เชื่อมกับ Module 05 ของคอร์สนี้ (ใช้ /compact ยังไง) — M02 ของ ai-sdlc สอนหลักคิดเบื้องหลังเต็มบท

💸 M03 · เศรษฐศาสตร์ของ Token

คำถามที่ถูก: ไม่ใช่ "โมเดลไหนถูกกว่า" แต่คือ "ต้นทุนต่องานที่เสร็จเท่าไร"

🗄️
Cache
1960s CPU cache → prompt caching: อ่านซ้ำถูกกว่าอ่านครั้งแรกมาก
🌊
Cascade
Viola–Jones 2001 → model routing: กรองด้วยของถูกก่อน จ่ายแพงเฉพาะเคสจำเป็น
แนวคิดทั้งสองขัดกันเองเมื่อใช้พร้อมกันกับ LLM — ต้องรู้จุดตัดสินใจว่าเมื่อไหร่ใช้อันไหน

📋 M04 · Requirements ที่ "ตรวจได้"

บทที่ให้ผลตอบแทนสูงสุดในคอร์ส — วางแผน 10 นาที ประหยัดการสั่งซ้ำเป็นชั่วโมง

❌ คำสั่ง"แก้บั๊กตรงหน้า checkout ให้หน่อย" — เสร็จเมื่อ "รู้สึกว่าใช่" — ผิดแล้วต้องอธิบายใหม่ทั้งหมด
VS
✅ ข้อกำหนด"ตะกร้าว่าง → ปุ่มชำระเงิน disabled และเทสต์ checkout.empty ต้องเขียว" — สคริปต์ตัดสินได้ — ผิดชี้ได้ว่าข้อไหนไม่ผ่าน

Prompt ที่ดีไม่ใช่คำสั่งที่เขียนเก่ง

แต่คือ ข้อกำหนดที่ตรวจได้ — หลักการเดียวกับ Module 04 ของคอร์สนี้ใน TDD RED phase

🏚️ M08 · Brownfield & Legacy Code

งานจริงไม่เริ่มจากโฟลเดอร์ว่าง — repo อายุ 6 ปี ไม่มีเทสต์ คนเขียนลาออกแล้ว กติกากลับด้านจาก greenfield

🌱 Greenfieldความเสี่ยง: ทำไม่เสร็จ
กลยุทธ์: ลุยได้เลย
VS
🏚️ Brownfieldความเสี่ยง: ทำของที่เคยใช้ได้ให้พัง
กลยุทธ์: สร้างตาข่ายก่อน แล้วค่อยขยับ

3 output ก่อนสั่งแก้อะไรเลย

1) แผนที่ระดับบน (โมดูลหลัก, อะไรเรียกอะไร) 2) เส้นทางของฟีเจอร์ (request → DB ทีละไฟล์) 3) รายการของที่ดูแปลก (โค้ดตายแล้ว, ชื่อขัดกัน, ของซ้ำ) — ข้อ 3 มีค่าที่สุด เพราะ agent ไม่มีความคุ้นเคยมาบดบัง มันเห็นสิ่งที่คนในทีมชินตาจนมองไม่เห็นแล้ว

🧪 M11 · Testing: เทสต์ที่ Agent เขียนเอง

Agent เขียนเทสต์ได้เร็วมาก — ทั้งข้อดีและปัญหา เพราะเทสต์ที่ผ่านไม่ได้แปลว่าโค้ดถูก

ความต่างสำคัญ: คนเขียนโค้ด+เทสต์เอง → เทสต์สะท้อนความเข้าใจ · agent เขียนทั้งคู่ → เทสต์สะท้อนสิ่งที่โค้ดทำ ไม่ใช่สิ่งที่โค้ดควรทำ

TDD (red→green→refactor, Kent Beck 1999-2002) คิดมาก่อน LLM 20 ปี เพื่อกันปัญหานี้พอดี — เหตุผลที่ Module 04 ของคอร์สนี้ห้าม agent แก้ไฟล์ test เองในรอบ GREEN

💉 M13 · Prompt Injection: ภัยที่รู้วันเกิด

โมเดลแยกไม่ออกระหว่างคำสั่งจากคุณ กับข้อความที่หน้าตาเหมือนคำสั่งในข้อมูลที่มันอ่าน

2022-09Riley Goodside สาธิต — ข้อความในอินพุตทำให้โมเดลเลิกทำตามคำสั่งเดิม
2022-09-12Simon Willison ตั้งชื่อ "prompt injection" เทียบกับ SQL injection
2023-02Indirect prompt injection — พิษมาจากของที่ agent ไปอ่านเอง ไม่ต้องมาจากผู้ใช้
2023→OWASP จัดเป็นอันดับ 1 (LLM01)
เชื่อมตรงกับกฎ untrusted-content ของระบบนี้เอง — เนื้อหาจากเว็บ/ไฟล์ที่ agent อ่าน ต้องถูก treat เป็น data ไม่ใช่ instruction เสมอ
