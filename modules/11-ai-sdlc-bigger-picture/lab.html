The Bigger Picture: AI Coding Agent SDLC

Lab นี้ไม่มีเนื้อหาใหม่ให้ implement — เป็น guided tour ให้เปิดคอร์ส ai-sdlc จริง แล้วติดตั้ง AI Hero skills มาทดลองใช้กับโปรเจกต์เล็กๆ เพื่อเห็นว่าแนวคิด spec-first/TDD ที่เรียนใน Module 04 ถูกทำเป็น production skill จริงยังไง

⏱ ~40-55 นาที 🌐 ต้องต่อเน็ตได้ (เปิดเว็บ + npx install) 🖥 ต้องมี Node.js/npx และ Claude Code (จาก Module 03) 📦 Module 11 (Optional/Enrichment)

Prerequisites

  • ผ่าน Module 03 (มี Claude Code ติดตั้งแล้ว, auth สำเร็จ)
  • ผ่าน Module 04 (เข้าใจ feature loop + TDD RED-GREEN-REFACTOR มาก่อน จะได้เทียบได้)
  • มี Node.js/npx ใช้งานได้ (เช็คด้วย npx --version)
  • ไม่บังคับต้องมี git repo จริงของทีม — ใช้ repo ทดลองใหม่ก็พอสำหรับ lab นี้

Objectives

  • สำรวจโครงสร้าง 15 module ของคอร์ส ai-sdlc และหาว่าโมดูลไหนตรงกับ gap ของทีมตัวเองมากที่สุด
  • ติดตั้ง AI Hero skill set จริงลงในโปรเจกต์ทดลอง
  • ลองรัน /grill-with-docs กับ feature เล็กๆ แล้วดูว่า artifact (CONTEXT.md, ADR) ถูกเขียนจริงยังไง
  • เปรียบเทียบ workflow นี้กับ feature loop ที่ทำใน Module 04 lab — เหมือน/ต่างกันตรงไหน
  • ตัดสินใจได้ว่า module ไหนของ ai-sdlc ควรเรียนต่อก่อนเป็นอันดับแรก ตามงานจริงของตัวเอง

1สำรวจโครงสร้างคอร์ส ai-sdlc

เปิดหน้า overview แล้วสำรวจ course-data จริงของทั้ง 15 module (ไม่ต้องเข้าเรียนตอนนี้)

curl -s "https://supachai-j.github.io/ai-sdlc/" -o /tmp/ai-sdlc-index.html
curl -s "https://supachai-j.github.io/ai-sdlc/assets/course-data.js" \
  | grep -oP '"title"\s*:\s*"[^"]*"'
Verify: ต้องเห็นรายชื่อ 15 module พิมพ์ออกมา (M01 กลไกภายในของ Agent ไปจนถึง M15 Operations/Governance) — ถ้าไม่มี output แปลว่า curl โดน block ให้เปิดผ่าน เบราว์เซอร์แทน

2เลือก 1 module ที่ตรงกับ gap ของทีมมากที่สุด

อ่านหัวข้อทั้ง 15 module ที่ได้จาก step 1 แล้วเขียนไฟล์บันทึกการตัดสินใจของตัวเอง

mkdir -p ~/module11-lab && cd ~/module11-lab
cat > my-priority.md << 'EOF'
# Module ai-sdlc ที่ควรเรียนก่อน

## Module ที่เลือก: M__ - (ชื่อ module)

## เหตุผล
- ปัญหาจริงที่ทีม/ตัวเองเจอ: ...
- ทำไม module นี้ตรงจุดที่สุด (ไม่ใช่ module อื่น): ...

## สิ่งที่คาดว่าจะได้หลังเรียน
- ...
EOF
Verify: เปิดไฟล์อ่านทวน — เหตุผลต้องอ้างอิงปัญหาที่เกิดขึ้นจริงกับตัวเอง/ทีม ไม่ใช่แค่ "ดูน่าสนใจ" — ถ้าตอบไม่ได้ว่าทำไมต้อง module นี้ไม่ใช่ module อื่น ให้กลับไปอ่านหัวข้อสรุปของแต่ละ module ใน slides.html อีกรอบ

3สร้างโปรเจกต์ทดลองสำหรับ AI Hero skills

mkdir -p ~/aihero-lab && cd ~/aihero-lab
git init -q
git config user.email "you@example.com"
git config user.name "Your Name"
echo "# AI Hero Skills Lab" > README.md
git add README.md
git commit -q -m "init: aihero skills lab"
Verify: git log --oneline ต้องแสดง commit แรก

4ติดตั้ง AI Hero skill set

ติดตั้งชุด skill ทั้งหมด (25 skills, MIT license, ใช้ได้กับ Claude Code/Cursor/Codex/Copilot)

npx skills@latest add mattpocock/skills
Verify: ต้องเห็นไฟล์ skill ใหม่ถูกเขียนลงในโปรเจกต์ (เช่นใต้ .claude/skills/ หรือ path ที่ installer แจ้ง) — เช็คด้วย find . -iname "*grill*"
ทางเลือก: ถ้าใช้ Claude Code และอยากได้ auto-update ให้ใช้ claude plugins install mattpocock-skills แทน (ติดตั้งเป็น managed read-only plugin จาก official marketplace แทนการ copy ไฟล์เข้าโปรเจกต์)

5ทดลองรัน /grill-with-docs กับ feature เล็กๆ

เปิด Claude Code ในโปรเจกต์นี้แล้วลองใช้ skill สัมภาษณ์เพื่อ align ก่อนเขียนโค้ดจริง — เทียบกับ Module 04 lab ที่คุณเขียน spec/test เองตรงๆ ไม่มี agent สัมภาษณ์

cd ~/aihero-lab
claude

ในเซสชัน Claude Code พิมพ์:

/grill-with-docs

(เมื่อถูกถาม ให้บอกว่า: "I want to add a function that calculates
a loyalty discount: customers with more than 5 orders get 15% off,
otherwise no discount")
Verify: ตอบคำถามที่ agent สัมภาษณ์กลับไปสัก 2-3 รอบ จนกว่า session จะจบ แล้วเช็คว่ามีไฟล์ใหม่เกิดขึ้นจริงไหม: 
find . -iname "CONTEXT.md" -o -path "*/adr/*"
ถ้าเจอ CONTEXT.md — เปิดอ่านดูว่าคำศัพท์ที่ agent สรุปตรงกับที่คุณตั้งใจไหม

6เปรียบเทียบกับ feature loop ของ Module 04

เขียนตารางเปรียบเทียบสั้นๆ ระหว่าง 2 workflow ที่เพิ่งทำจริงทั้งคู่

cat >> ~/module11-lab/my-priority.md << 'EOF'

## เทียบ workflow: Module 04 feature loop vs /grill-with-docs

| | Module 04 feature loop | /grill-with-docs |
|---|---|---|
| จุดเริ่ม | เขียน branch + prompt ตรงๆ | ถูกสัมภาษณ์ก่อนเริ่ม |
| Artifact ที่ได้ | commit + PR diff | CONTEXT.md + ADR + (แล้วค่อย commit) |
| เหมาะกับ | งานที่ scope ชัดแล้ว | งานที่ scope ยังไม่นิ่ง ต้อง align กับ agent ก่อน |
EOF
Verify: เติมช่องว่างในตารางด้วยประสบการณ์จริงที่เพิ่งได้จาก step 5 — ไม่ใช่แค่ท่องนิยาม
Troubleshoot: /grill-with-docs รันแล้วไม่มี CONTEXT.md หรือ ADR โผล่มาเลย

ตามเอกสารต้นทาง นี่มี 2 สาเหตุที่เป็นไปได้:

  • สาเหตุปกติ: session ที่ยังไม่มีคำศัพท์ใหม่หรือการตัดสินใจที่เข้าเกณฑ์ ครบ 3 ข้อ (กลับยาก + surprising + trade-off จริง) พร้อมกัน จะไม่มีอะไรถูกเขียนลงไฟล์เลย — ลองใช้ feature ที่มีความซับซ้อนมากขึ้นอีกหน่อย
  • Known bug: ถ้ารันภายใต้ orchestration layer อื่น (เช่น spec-driven-development wrapper หรือ multi-agent framework ที่เรียก skill นี้เป็น step หนึ่ง) ส่วนเขียนไฟล์อาจไม่ทำงานเงียบๆ ทั้งที่ interview ยังรันอยู่ปกติ — ตรวจ working directory ก่อนเชื่อผลลัพธ์ของ session

ที่มา: aihero.dev/grill-with-docs — Common Questions

Troubleshoot: skill ถามทุกอย่างพร้อมกันไม่มี recommendation เลย

/grill-with-docs คือ 1 บรรทัดที่ delegate ไปยัง skill อื่น 2 ตัว (grilling สำหรับ interview, domain-modeling สำหรับการเขียน) — ถ้า agent ไม่โหลด dependency ทั้งสองตัวนี้ พฤติกรรมจะผิดแบบนี้พอดี ลอง reinstall ทั้งชุดใหม่แทนการติดตั้งแค่ skill เดียว

สรุป & ต่อยอด

Lab นี้ไม่ได้สอนเนื้อหาใหม่ แต่เปิดให้เห็น 2 อย่าง: (1) มี "แผนที่การเรียนรู้" ที่ลึกกว่า คอร์สนี้อยู่แล้ว (ai-sdlc) สำหรับหัวข้อที่ยังไม่ครอบคลุม และ (2) หลักการที่เรียนใน Module 04/11 ของคอร์สนี้ (spec-first, TDD) ถูกนำไปทำเป็น production tool จริงที่คนอื่นใช้งานกันแล้ววันนี้

  • เลือก module ai-sdlc 1 อันจาก step 2 แล้วเริ่มเรียนจริงในสัปดาห์นี้
  • ลอง /code-review ของ AI Hero กับ diff จริงที่เพิ่งทำใน Module 04 lab เทียบกับ git diff | claude -p 'review...' pattern เดิม — คุณภาพ feedback ต่างกันแค่ไหน
  • ถ้าทีมตัดสินใจ adopt skill set นี้จริง ให้กลับไปอ่าน Module 08 (Governance) ก่อน — skill ที่เขียนไฟล์ลง repo อัตโนมัติต้องผ่าน review เหมือน code ปกติ
