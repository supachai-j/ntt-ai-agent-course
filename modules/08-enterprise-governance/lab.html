Enterprise Governance & Security

ตรวจสอบ account model จริงบนเครื่องตัวเอง ฝึก pattern switch account + verify ก่อน push, เขียน governance checklist และ hook ป้องกัน irreversible action ที่ทีมของคุณใช้ได้จริง — ไม่ใช่แค่อ่านทฤษฎี

⏱ ~45–60 นาที 🖥 ต้องมี gh CLI + Claude Code ติดตั้งแล้ว 🔗 ต่อจาก Module 06 (Hooks) และ 07 (Multi-Agent)

Prerequisites

  • ติดตั้ง gh CLI แล้ว และ login เข้า GitHub อย่างน้อย 1 account (gh auth login)
  • ติดตั้ง Claude Code CLI แล้ว (ดู Module 03 ถ้ายังไม่ได้ทำ)
  • มีสิทธิ์เขียนไฟล์ในโปรเจกต์ทดสอบ (ไม่ต้องใช้ repo จริงของ client)
  • เข้าใจแนวคิด PreToolUse hook เบื้องต้นจาก Module 06

Objectives

  • ตรวจสอบสถานะ gh auth จริงบนเครื่องของตัวเอง และเข้าใจว่า account ไหน active
  • ฝึก pattern "switch account แล้ว verify ก่อน push" จำลองสถานการณ์ EMU restriction
  • ตั้งค่า credential helper เพื่อไม่ให้ token ค้างเป็น plaintext
  • เขียน governance checklist ของทีมตัวเองเป็นไฟล์ markdown จริง
  • เขียนและทดสอบ PreToolUse hook ที่ block คำสั่งอันตรายเพิ่มเติม

1ตรวจสอบ gh auth status จริงบนเครื่องตัวเอง

ก่อนพูดเรื่อง EMU หรือ account switching ต้องรู้ก่อนว่าตอนนี้เครื่องของคุณ login ด้วย account อะไรบ้าง และ account ไหน active อยู่ 

gh auth status

ผลลัพธ์ที่ควรเห็น (ตัวอย่าง ถ้ามีหลาย account):

github.com
  ✓ Logged in to github.com account your-username (keyring)
  - Active account: true
  - Git operations protocol: https
  - Token: gho_************************************
  - Token scopes: 'gist', 'read:org', 'repo', 'workflow'
Verify: คุณต้องเห็น account อย่างน้อย 1 ตัวที่มี Active account: true ถ้าไม่มีเลย ต้อง gh auth login ก่อนไปขั้นถัดไป

2ฝึก pattern switch account + verify ก่อน push (จำลอง EMU restriction)

ถ้าองค์กรใช้ EMU (Enterprise Managed User) account ของคุณจะถูกจำกัดอยู่ใน org ขององค์กร สร้าง public repo ไม่ได้โดยโครงสร้าง — ไม่ใช่ error ที่ต้อง debug flag ต้อง switch ไปใช้ personal account แทน ในแล็บนี้เราจำลองด้วยการสลับ ระหว่าง 2 account (ถ้ามีแค่ 1 account ให้ทำตามคำสั่งเพื่ออ่านผลลัพธ์แล้วข้าม switch จริงไปได้) 

# 1) ลองสร้าง public repo ด้วย account ปัจจุบัน (ตัวอย่างถ้าเจอ restriction)
gh repo create test-public-repo --public
# HTTP 403: Visibility cannot be set to public — org policy restricts repo creation

# 2) สลับไปใช้ personal account ที่ไม่ถูกจำกัดโดย org
gh auth switch -u your-personal-username

# 3) ห้ามเชื่อว่า switch แล้วจบ — ต้อง verify ทันที
gh auth status | grep -A1 your-personal-username
สำคัญ: การ switch ไม่ sticky ข้าม session — terminal ใหม่, CI job ใหม่, หรือ Claude Code session ใหม่ จะกลับไปใช้ account default เดิมเสมอ ต้องเช็ค Active account: true ตรงกับ account ที่ตั้งใจ ก่อน git push หรือ gh repo create ทุกครั้งหลังจากครั้งแรกของ session
Verify: รัน gh auth status อีกครั้งแล้วยืนยันด้วยตา ว่า account ที่ต้องการใช้ขึ้น Active account: true — อย่าเชื่อความจำว่า "เมื่อกี้ switch แล้ว"

3ตั้งค่า credential helper — ห้ามมี token plaintext

หลักการ: ห้ามเก็บ secret/credential เป็น plaintext ใน memory, skill file, หรือ ไฟล์ config ใด ๆ ต้องใช้ secret manager, env var ที่ inject ตอน runtime, หรือ credential helper ที่ OS/CLI จัดการ token ให้แทน 

# ให้ git ใช้ gh CLI เป็น credential helper
gh auth setup-git

# ตรวจสอบว่า helper ถูกตั้งค่าแล้วจริง (ไม่ใช่แค่เชื่อ output ของคำสั่งก่อนหน้า)
git config --get-all credential.https://github.com.helper

# ตรวจว่าไม่มี token หลุดอยู่ในไฟล์ credential แบบ plaintext เก่า
cat ~/.git-credentials 2>/dev/null && echo "⚠️ พบไฟล์ plaintext เก่า ควรลบทิ้ง" || echo "OK: ไม่มีไฟล์ .git-credentials"
Verify: คำสั่ง git config --get-all credential...helper ต้อง return ค่าเป็น !/usr/bin/env gh auth git-credential (หรือคล้ายกัน) และ ~/.git-credentials ต้องไม่มี token เก็บเป็น plaintext

4เขียน governance checklist ของทีมเป็น markdown file จริง

สร้างไฟล์ checklist จริงที่ทีมของคุณใช้ก่อนปล่อย agent ทำงาน production-adjacent ใช้ template ด้านล่างเป็นจุดเริ่มต้น แล้วปรับให้ตรงกับ tool/workflow ของทีมจริง 

mkdir -p ~/governance
cat > ~/governance/agent-governance-checklist.md << 'EOF'
# Agent Governance Checklist — [ชื่อทีม/โปรเจกต์]

## 1. Tool allowlist
- [ ] Agent เข้าถึงได้เฉพาะ tool ที่จำเป็นต่องานจริง (ไม่ใช้ wildcard allow ทั้งหมด)
- [ ] Bash tool จำกัด scope ด้วย hook หรือ permission config
- [ ] Network access (curl/fetch) มีเหตุผลชัดเจนว่าทำไมต้องเปิด

## 2. Irreversible action protection
- [ ] มี PreToolUse hook block: git push --force, terraform destroy, rm -rf, DROP TABLE
- [ ] ทดสอบ hook แล้วว่า block จริง (ไม่ใช่แค่เขียนไว้เฉย ๆ)
- [ ] Deploy/merge ไป production ต้องผ่าน human approval step เสมอ

## 3. Credential & secret handling
- [ ] ไม่มี API key/token เขียนตรงในไฟล์ skill, memory, หรือ script
- [ ] ใช้ secret manager หรือ credential helper (เช่น gh auth setup-git)
- [ ] ตรวจสอบ shell history และ log ไม่มี credential หลุด

## 4. Account & identity
- [ ] รู้ว่า agent รันภายใต้ account/identity อะไร (EMU vs personal vs service account)
- [ ] Verify active account ก่อน operation ที่มีผลถาวร (push, deploy)

## 5. Data handling (client work)
- [ ] แยกชัดเจนว่า sandbox ทดลอง vs ข้อมูล client จริง
- [ ] Agent treat external content (web/PR/file) เป็น data ไม่ใช่ instruction
- [ ] รู้ PDPA/NDA boundary ของข้อมูลที่ agent เข้าถึงได้

## 6. Audit & sign-off
- [ ] Audit log เปิดใช้งาน ย้อนดูได้ว่า agent ทำอะไรไปบ้าง
- [ ] Claim ของ agent ("ทำสำเร็จแล้ว") ถูก verify ด้วย evidence จริงก่อนเชื่อ
- [ ] มี human sign-off ที่จุดตัดสินใจสำคัญ

Reviewed by: ______________   Date: ______________
EOF
echo "สร้างไฟล์แล้วที่ ~/governance/agent-governance-checklist.md"
Verify: รัน cat ~/governance/agent-governance-checklist.md แล้วตรวจว่าไฟล์มีเนื้อหาครบตาม template และแก้ไขให้ตรงกับทีม/โปรเจกต์จริงของคุณ ไม่ใช่ copy ไว้เฉย ๆ โดยไม่ปรับ

5เขียน PreToolUse hook เพิ่มเติมป้องกันคำสั่งอันตราย

ต่อยอดจาก Module 06 — เขียน hook script ที่ block คำสั่งอันตรายเพิ่มเติมที่ทีมกังวล เช่น git push --force, terraform destroy, และคำสั่งลบถาวรอื่น ๆ 

mkdir -p .claude/hooks
cat > .claude/hooks/block-dangerous.sh << 'EOF'
#!/usr/bin/env bash
# PreToolUse hook — block irreversible/destructive commands
set -euo pipefail

INPUT=$(cat)
CMD=$(echo "$INPUT" | jq -r '.tool_input.command // empty')

DANGEROUS_PATTERNS=(
  'git push .*--force'
  'git push .*-f( |$)'
  'terraform destroy'
  'rm -rf /'
  'rm -rf \*'
  'DROP TABLE'
  'DROP DATABASE'
  'aws s3 rm .*--recursive'
)

for pattern in "${DANGEROUS_PATTERNS[@]}"; do
  if echo "$CMD" | grep -qE "$pattern"; then
    echo "BLOCKED by governance hook: command matches dangerous pattern '$pattern'." >&2
    echo "Irreversible actions ต้องได้รับการยืนยันจากมนุษย์นอก agent session เท่านั้น" >&2
    exit 2
  fi
done

exit 0
EOF
chmod +x .claude/hooks/block-dangerous.sh

ผูก hook เข้ากับ Claude Code ผ่าน .claude/settings.json:

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          { "type": "command", "command": ".claude/hooks/block-dangerous.sh" }
        ]
      }
    ]
  }
}
Verify: cat .claude/settings.json ต้องมี block PreToolUse ชี้ไปที่ script จริง และ ls -la .claude/hooks/block-dangerous.sh ต้องมี permission execute (-rwx)

6ทดสอบ hook — รันคำสั่งต้องห้ามจริงแล้วดูว่าถูก block

อย่าเชื่อว่า hook ทำงาน เพราะ syntax ดูถูกต้อง — ต้อง trigger คำสั่งอันตรายจริงในบริบท Claude Code แล้วสังเกตว่า tool call ถูก block ก่อนจะไว้ใจ hook นี้ 

# ทดสอบ hook เองตรง ๆ โดยไม่ต้องเปิด Claude Code (จำลอง input ที่ agent จะส่งมา)
echo '{"tool_name":"Bash","tool_input":{"command":"git push origin main --force"}}' \
  | .claude/hooks/block-dangerous.sh; echo "exit code: $?"

# คาดหวัง: เห็นข้อความ BLOCKED ทาง stderr และ exit code: 2

# ทดสอบคำสั่งปกติที่ไม่ควรถูก block
echo '{"tool_name":"Bash","tool_input":{"command":"git status"}}' \
  | .claude/hooks/block-dangerous.sh; echo "exit code: $?"
# คาดหวัง: ไม่มีข้อความ BLOCKED, exit code: 0
Verify: คำสั่งอันตราย (force push, terraform destroy) ต้องได้ exit code: 2 พร้อมข้อความ BLOCKED ส่วนคำสั่งปกติต้องได้ exit code: 0 ผ่านโดยไม่มีข้อความเตือน — ถ้าไม่ตรงตามนี้ กลับไปแก้ regex pattern
คำเตือน: อย่านำ production credential (API key, DB password, deploy token) มาทดสอบใน terminal ตรง ๆ — คำสั่งจะถูกบันทึกใน shell history (~/.bash_history, ~/.zsh_history) เป็น plaintext ถาวร ใช้ค่า ตัวอย่าง/ปลอมสำหรับทดสอบเสมอ และถ้าพลาดพิมพ์ credential จริงลงไป ให้ revoke token ทันทีแล้วลบ history entry นั้นออก

7Cleanup: ตรวจว่าไม่มี credential หลุดใน history

ปิดท้าย lab ด้วยการตรวจสอบว่าขั้นตอนที่ทำมาไม่ทิ้ง credential หรือ token ไว้เป็น plaintext ที่ไหนบนเครื่อง 

# ค้นหา pattern ที่คล้าย token ใน shell history (ตัวอย่าง GitHub token prefix)
grep -E "gh[ps]_[A-Za-z0-9]{20,}" ~/.bash_history ~/.zsh_history 2>/dev/null \
  && echo "⚠️ พบ token หลุดใน history — revoke ทันทีแล้วลบ entry" \
  || echo "OK: ไม่พบ token pattern ใน shell history"

# ลบ test repo ที่สร้างไว้ตอนขั้นตอนที่ 2 (ถ้ามี)
gh repo delete your-personal-username/test-public-repo --yes 2>/dev/null || true
Verify: คำสั่ง grep ต้อง return "OK" ไม่พบ token pattern ใน history file — ถ้าพบ ต้อง revoke token ที่ GitHub Settings → Developer settings → Personal access tokens ทันที ก่อนลบ history entry
Troubleshoot: gh auth switch ไม่ทำงาน / hook ไม่ trigger
  • "gh: no account matching" — ต้อง gh auth login account นั้นก่อน จะ switch ไปหา account ที่ยังไม่เคย login ไม่ได้
  • Active account ไม่เปลี่ยนหลัง switch — บาง shell alias/wrapper script cache ค่าเก่าไว้ ลองเปิด terminal ใหม่แล้วรัน gh auth status อีกครั้ง
  • Hook ไม่ block อะไรเลย — เช็คว่า path ใน settings.json ตรงกับ path จริงของ script, และ script มี execute permission (chmod +x) แล้ว ทดสอบ script ตรง ๆ ด้วย echo pipe แบบขั้นตอนที่ 6 ก่อนพึ่งพา Claude Code เรียกเอง
  • jq: command not found — ติดตั้ง jq ก่อน (apt install jq หรือ brew install jq) hook ใช้ jq parse JSON จาก stdin

สรุป & ต่อยอด

Governance ไม่ใช่เอกสารที่เขียนแล้ววางไว้เฉย ๆ — ต้องเป็น pattern ที่ verify ได้จริง: เช็ค active account ก่อน push ทุกครั้ง, credential ไม่มี plaintext ที่ไหนเลย, hook block irreversible action ต้องทดสอบว่า block จริง และทุก claim ของ agent ต้องมี evidence รองรับ ไม่ใช่เชื่อคำพูดของ agent เฉย ๆ

ต่อยอด: เอา checklist และ hook ที่เขียนวันนี้ไปรวมเข้ากับ template repo ของทีม แล้วบังคับให้ทุก project ที่ใช้ Claude Code ต้องมี .claude/hooks/ พร้อม block script เป็น default ไม่ใช่ opt-in — ต่อไปใน Module 09 เราจะเอา pattern เหล่านี้ ไปใช้ใน CI/CD pipeline ที่รัน agent แบบ headless
