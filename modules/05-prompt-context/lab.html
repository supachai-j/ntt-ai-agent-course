Lab · Module 05

Prompt Engineering & Context Management

เขียน CLAUDE.md จริงจาก mini-project, ทดลอง /context และ /compact ใน interactive session จริง แล้วเปรียบเทียบพฤติกรรม agent ก่อน/หลังใส่ CLAUDE.md ที่ดีกับที่แย่ — วัดผลจากคุณภาพ output และจำนวน turn ที่ใช้จริง ไม่ใช่ความรู้สึก

⏱ 60–75 นาที 🖥 ต้องมี Claude Code CLI ติดตั้งและ login แล้ว 📦 ต้องมี tmux 📁 ใช้ repo/โปรเจกต์จาก Module 03 หรือสร้างใหม่ก็ได้

Prerequisites

  • ผ่าน Module 03 (Claude Code Fundamentals) — รู้จัก REPL, print mode, CLAUDE.md เบื้องต้น
  • claude --version ต้องขึ้น v2.x ขึ้นไป และ claude auth status ต้อง login แล้ว
  • มี git repo หรือ folder โปรเจกต์เล็กๆ ที่มีโค้ดจริงอยู่บ้าง (ใช้ของ module ก่อนก็ได้ หรือ clone repo ตัวอย่างที่มีในเครื่อง)
  • ติดตั้ง tmux แล้ว (tmux -V เพื่อเช็ค)

Objectives

  • เขียน CLAUDE.md ของโปรเจกต์จริงที่มี instruction แบบ specific ไม่ใช่ vague
  • ใช้ /context อ่านค่า context window usage และตีความ threshold ได้
  • ใช้ /compact [focus] บีบอัด context พร้อมยืนยันว่า CLAUDE.md ยังอยู่หลัง compact
  • เปรียบเทียบ agent output ก่อน/หลังมี CLAUDE.md ที่ดี ด้วย prompt เดียวกัน
  • ปรับปรุง prompt แย่ให้ดีขึ้นแล้ววัดผลต่างจริงจากจำนวน turn และคุณภาพ output

1เตรียมโปรเจกต์ทดลอง

ใช้โปรเจกต์เดิมจาก Module 03/04 หรือสร้างโฟลเดอร์เล็กๆ ใหม่ที่มีโค้ดจริงพอทดลองได้ — ต้องมีไฟล์โค้ดอย่างน้อย 2-3 ไฟล์ ไม่ใช่ folder ว่าง

mkdir -p ~/lab05-project/src
cd ~/lab05-project
git init

cat > src/api.py << 'EOF'
def fetch_user(user_id):
    # TODO: no error handling yet
    response = requests.get(f"https://api.example.com/users/{user_id}")
    return response.json()

def create_order(items, user_id):
    total = sum(item['price'] for item in items)
    return {"user_id": user_id, "items": items, "total": total}
EOF

git add -A && git commit -m "init lab05 project"
Verify: ls src/ ต้องเห็น api.py และ git log --oneline ต้องมี commit แรกแล้ว

2Baseline: รัน prompt แย่ (vague) โดยไม่มี CLAUDE.md

เปิด tmux session แล้วรัน Claude Code แบบ interactive — ยังไม่สร้าง CLAUDE.md ใดๆ ตอนนี้ ทดสอบ prompt ที่จงใจเขียนแบบคลุมเครือ

tmux new-session -d -s lab05 -x 140 -y 40
tmux send-keys -t lab05 'cd ~/lab05-project && claude' Enter
sleep 4
tmux send-keys -t lab05 Enter   # ยอมรับ workspace trust dialog ถ้าขึ้นมา

ส่ง prompt แย่ตัวนี้เข้าไป (จงใจคลุมเครือ — นี่คือ "prompt แย่" ที่โจทย์ให้ปรับปรุงใน Step 5):

tmux send-keys -t lab05 'Make the api.py file better' Enter
sleep 20
tmux capture-pane -t lab05 -p -S -80 > ~/lab05-project/run-A-baseline.txt
cat ~/lab05-project/run-A-baseline.txt
Verify: เปิด run-A-baseline.txt แล้วบันทึก 2 ค่า — (1) จำนวน turn/tool-call ที่ agent ใช้ก่อนถามกลับหรือจบงาน (2) agent ตีความ "better" เป็นอะไรบ้าง (error handling? type hints? อื่นๆ) มักจะเดาไม่ตรงกับที่ทีมต้องการ เพราะ prompt ไม่ได้บอกเกณฑ์ชัดเจน
สังเกต: ถ้า agent ถามกลับเพื่อ clarify นั่นคือสัญญาณว่า prompt คลุมเครือเกินไปจนมันต้องเดา — นับเป็น 1 correction cycle ที่เสียเวลา

3เขียน CLAUDE.md ของโปรเจกต์นี้จริง

ล้าง state ก่อน (/clear) แล้วรัน /init เพื่อให้ Claude generate CLAUDE.md เริ่มต้น จากนั้นแก้ไขให้ specific ตามหลัก Module นี้ — เน้นสิ่งที่วัดผลได้จริง ไม่ใช่คำคลุมๆ

tmux send-keys -t lab05 '/clear' Enter
sleep 2
tmux send-keys -t lab05 '/init' Enter
sleep 15
tmux capture-pane -t lab05 -p -S -40

เปิด CLAUDE.md ที่ถูกสร้างแล้วแก้ให้มีกฎที่ specific เพิ่มเข้าไป (แก้ไฟล์นี้นอก tmux ด้วย editor ปกติ หรือใช้ /memory ใน session):

# lab05-project

## Code Standards
- Python: 4-space indentation, type hints บน public function ทุกตัว
- ทุก HTTP call ต้อง wrap ด้วย try/except และ raise ค่า error
  ที่มี context (ห้าม bare `except:` และห้าม swallow exception เงียบๆ)
- ฟังก์ชันห้ามยาวเกิน 40 บรรทัด — ถ้าเกินให้แตกฟังก์ชันย่อย

## Testing
- ทุกฟังก์ชันใน src/ ต้องมี unit test คู่กันใน tests/
- รัน `pytest --cov=src` ก่อน commit — coverage ต้อง ≥ 80%

## Git
- Commit message ใช้ conventional commits: feat/fix/refactor/test
Verify: cat ~/lab05-project/CLAUDE.md ต้องมีกฎที่วัดผลได้จริง (ตัวเลข, ชื่อ tool, threshold ชัดเจน) ไม่ใช่ประโยคกว้างๆ แบบ "write good code"

4รัน prompt เดิมซ้ำ พร้อม CLAUDE.md แล้ว

reset git ให้ api.py กลับไปสภาพเดิม (undo การแก้จาก Step 2 ถ้ามี) แล้วเริ่ม session ใหม่ที่โหลด CLAUDE.md เข้ามาอัตโนมัติ ส่ง prompt แย่ตัวเดิมเป๊ะๆ

cd ~/lab05-project
git checkout -- src/api.py    # คืนไฟล์กลับสภาพ baseline

tmux send-keys -t lab05 '/clear' Enter
sleep 2
tmux send-keys -t lab05 'Make the api.py file better' Enter
sleep 25
tmux capture-pane -t lab05 -p -S -100 > ~/lab05-project/run-B-with-claudemd.txt
cat ~/lab05-project/run-B-with-claudemd.txt
Verify: เทียบ run-A-baseline.txt กับ run-B-with-claudemd.txt — Run B ควรมี error handling ตาม pattern ที่กำหนด, type hints, และไม่ต้องถามกลับเพราะ CLAUDE.md ให้เกณฑ์ชัดแล้ว นับจำนวน tool-call/turn ของทั้งสอง run เทียบกันจริง (ดูจากบรรทัดที่ agent เรียก tool ใน capture)

5Exercise: ปรับปรุง prompt แย่ด้วยตัวเอง

ต่อไปนี้คือ prompt แย่อีกตัวหนึ่ง — เขียนใหม่ให้ specific ตามหลัก Module นี้ (ระบุเกณฑ์, ตัวเลข, tool ที่ใช้) แล้วรันเทียบทั้งสองแบบ

Prompt แย่ (ต้นฉบับ):
"Add tests for create_order"

ตัวอย่างการปรับปรุง (ห้ามลอกตรงๆ — ปรับให้เข้ากับโปรเจกต์จริงของคุณ):

Prompt ที่ปรับปรุงแล้ว:
"Add pytest unit tests for create_order() in tests/test_api.py
covering: (1) normal case with 2+ items, (2) empty items list,
(3) items with float prices needing rounding. Use pytest fixtures,
no mocking needed since create_order has no I/O. Run
`pytest tests/test_api.py -v` after writing and paste the output."
tmux send-keys -t lab05 '/clear' Enter
sleep 2
# รันแบบ vague ก่อน แล้ว capture
tmux send-keys -t lab05 'Add tests for create_order' Enter
sleep 20
tmux capture-pane -t lab05 -p -S -80 > ~/lab05-project/run-C-vague-prompt.txt

tmux send-keys -t lab05 '/clear' Enter
sleep 2
# รันแบบ specific ที่ปรับปรุงแล้ว
tmux send-keys -t lab05 'Add pytest unit tests for create_order() in tests/test_api.py covering: (1) normal case with 2+ items, (2) empty items list, (3) items with float prices needing rounding. Use pytest fixtures, no mocking needed. Run pytest -v after writing and paste the output.' Enter
sleep 25
tmux capture-pane -t lab05 -p -S -100 > ~/lab05-project/run-D-specific-prompt.txt
Verify: เทียบไฟล์ test ที่ได้จาก run C vs run D — run D ควรมี edge case ครบตามที่ระบุ (empty list, float rounding) ในขณะที่ run C มักจะได้แค่ happy-path test เดียว เพราะ prompt ไม่ได้บอก edge case ที่ต้องการ

6ตรวจ context usage ด้วย /context

ณ จุดนี้ session ควรมีประวัติสะสมพอสมควรจากหลาย run — ลองรัน /context เพื่อดูค่าจริง

tmux send-keys -t lab05 '/context' Enter
sleep 3
tmux capture-pane -t lab05 -p -S -40

อ่านค่า usage % ที่ได้ แล้วจับคู่กับ threshold:

ค่าที่เห็นความหมายต้องทำอะไรไหม
< 70%Normalทำงานต่อได้ปกติ
70–85%Warningเริ่มพิจารณา /compact
> 85%Dangerควร /compact ก่อนสั่งงานต่อ
Verify: จดค่า % ที่เห็นจริงจากคำสั่ง /context — ถ้ายังต่ำกว่า 70% ให้รัน prompt เพิ่มอีก 2-3 รอบ (เช่นขอให้ agent อ่านไฟล์ใหญ่ๆ) เพื่อดันตัวเลขขึ้นแล้วรัน /context ซ้ำเพื่อเห็นความต่าง

7บีบอัดด้วย /compact และยืนยัน CLAUDE.md ยังอยู่

tmux send-keys -t lab05 '/compact focus on the CLAUDE.md rules and testing work' Enter
sleep 15
tmux capture-pane -t lab05 -p -S -60

# หลัง compact เสร็จ ถามคำถามที่ต้องใช้กฎจาก CLAUDE.md เพื่อยืนยันว่ามันยังจำได้
tmux send-keys -t lab05 'What indentation and coverage threshold does this project use, per CLAUDE.md?' Enter
sleep 10
tmux capture-pane -t lab05 -p -S -30
Verify: agent ต้องตอบ "4-space indentation" และ "coverage ≥ 80%" ถูกต้อง แม้ conversation history ก่อนหน้าจะถูกบีบอัดไปแล้ว — นี่คือหลักฐานว่า CLAUDE.md persist ผ่าน /compact จริง ไม่ใช่แค่ทฤษฎี
ถ้าตอบผิดหรือจำไม่ได้: เช็คว่า CLAUDE.md ยังอยู่ที่ root ของโปรเจกต์ (cat CLAUDE.md) และ session เปิดจาก working directory เดียวกับที่มีไฟล์นั้นจริง — CLAUDE.md ที่อยู่ผิด path จะไม่ถูก auto-load

8Bonus: แยก CLAUDE.md เป็น rules directory

เมื่อ CLAUDE.md เริ่มยาวเกิน 1 หน้าจอ ลองแยกเป็น .claude/rules/*.md ตามหมวด

mkdir -p ~/lab05-project/.claude/rules
cat > ~/lab05-project/.claude/rules/testing.md << 'EOF'
# Testing rules
- ทุกฟังก์ชันใน src/ ต้องมี unit test คู่กันใน tests/
- รัน `pytest --cov=src` ก่อน commit — coverage ต้อง >= 80%
EOF

cat > ~/lab05-project/.claude/rules/code-style.md << 'EOF'
# Code style rules
- Python: 4-space indentation, type hints บน public function ทุกตัว
- ทุก HTTP call ต้อง wrap ด้วย try/except พร้อม context ใน error
EOF

tmux send-keys -t lab05 '/clear' Enter
sleep 2
tmux send-keys -t lab05 'What testing coverage threshold does this project require?' Enter
sleep 10
tmux capture-pane -t lab05 -p -S -30
Verify: agent ต้องตอบ "80%" ได้ถูกต้องแม้กฎนั้นย้ายไปอยู่ใน .claude/rules/testing.md แล้ว ไม่ได้อยู่ใน CLAUDE.md หลักโดยตรง — ยืนยันว่าไฟล์ใน rules directory ถูก auto-load เหมือนกัน
Troubleshoot: tmux capture-pane ว่างเปล่าหรือ Claude ไม่ตอบ

สาเหตุที่พบบ่อย:

  • sleep สั้นเกินไป: agentic loop ที่มี tool call หลายรอบใช้เวลา 15-30 วินาทีขึ้นไป — เพิ่ม sleep แล้ว capture ใหม่
  • ยังติด dialog: เช็คว่า workspace trust dialog หรือ permission prompt ค้างอยู่หรือไม่ ด้วย tmux capture-pane -t lab05 -p -S -10 แล้วส่ง Enter เพิ่ม
  • session ตาย: เช็คว่า session ยังอยู่ด้วย tmux ls — ถ้าไม่มี lab05 แสดงว่า process crash ต้องเปิดใหม่
  • claude ไม่ login: รัน claude auth status นอก tmux ก่อนเริ่ม lab เพื่อยืนยัน auth
Troubleshoot: /compact แล้ว agent ลืมกฎใน CLAUDE.md

ปกติ CLAUDE.md ควร survive การ compact เพราะถูก re-inject เป็น system context ใหม่เสมอ ถ้าไม่รอด:

  • เช็ค path — CLAUDE.md ต้องอยู่ที่ root ของ working directory ที่เปิด claude ขึ้นมา ไม่ใช่ subfolder
  • เช็คว่าไม่ได้เปิด session ด้วย --bare flag ซึ่งข้าม CLAUDE.md loading ไปเลย
  • ลอง /memory เพื่อเปิดดู CLAUDE.md ที่ agent เห็นจริง เทียบกับไฟล์บน disk

สรุป & ต่อยอด

Lab นี้พิสูจน์ด้วยมือว่า instruction ที่ specific ลด correction cycle ได้จริง (เทียบ run A vs B, run C vs D) และ CLAUDE.md เป็นชั้น context ที่ persist ข้าม /compact ต่างจาก user prompt รายรอบที่หายไปเมื่อ context ถูกบีบอัด — ส่วน rules directory pattern ช่วยให้ทีมที่มีกฎเยอะ scale ได้ โดยไม่ทำให้ CLAUDE.md กลายเป็นไฟล์ยักษ์ที่ merge conflict ตลอด

ต่อยอด: ลองเขียน skill จริงในรูปแบบ declarative lesson จาก bug หรือ pattern ที่เจอในงานจริงของทีมคุณ แล้วเก็บไว้ใน .claude/skills/ — Module 06 จะพาไปดูวิธี gate การทำงานของ agent ด้วย hooks และต่อ MCP server เข้ากับระบบภายนอก ซึ่งเป็นจุดที่ prompt injection awareness จาก module นี้สำคัญมากขึ้นไปอีก เพราะ agent จะเริ่มดึงข้อมูลจากแหล่งที่ควบคุมไม่ได้โดยตรง
