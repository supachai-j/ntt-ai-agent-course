กฎง่ายๆ ในการเลือกโหมด

ควบคุมทีละ step → Interactive  |  รันใน pipeline ไม่มีคนดู → Print mode

Print Mode ในทางปฏิบัติ

# รันงานเดียวแล้วจบ ไม่มี interactive dialog
claude -p "explain what this repo does" --max-turns 3

# เอาผลลัพธ์เป็น JSON เพื่อ parse ต่อใน script
claude -p "list files" --output-format json | jq -r '.result'
Print mode ข้าม trust dialog อัตโนมัติ — รันเฉพาะใน directory ที่เชื่อถือได้เท่านั้น

CLAUDE.md — Project Memory

🧠ไฟล์ที่ Claude Code auto-load ทุกครั้งที่เริ่ม session

ไม่ใช่ prompt แต่คือ "ความจำถาวร" — ยิ่งเขียนดี agent ยิ่งเดาโครงสร้างโปรเจกต์ถูกโดยไม่ต้องถามซ้ำ

ตัวอย่าง CLAUDE.md

# Project: internal-billing-api

## Architecture
Node.js + Express REST API, PostgreSQL via Prisma ORM.
Entry point: src/server.js. Routes in src/routes/.

## Key commands
- Run dev server: npm run dev
- Run tests: npm test
- Lint: npm run lint
- Build: npm run build

## Code standards
- Use TypeScript strict mode, no `any`
- All routes need input validation via zod
- Write a test for every new endpoint
- Follow existing error-handling pattern in src/lib/errors.js

CLAUDE.md — Hierarchy

Global — ~/.claude/CLAUDE.mdทุกโปรเจกต์ของ user
Project — ./CLAUDE.mdเฉพาะโปรเจกต์ — commit เข้า git
Local — .claude/CLAUDE.local.mdเฉพาะเครื่อง — gitignored

Trust Dialog & Workspace Safety

ครั้งแรกที่เปิด directory ใหม่ (interactive mode)

Claude Code จะถามว่า "Do you trust the files in this folder?" ก่อนอ่าน/รันอะไรในโฟลเดอร์นั้น

Trust dialog ถูกข้ามอัตโนมัติใน print mode — รันเฉพาะ directory ที่ควบคุม/เชื่อถือได้ ปรับเพิ่มได้ผ่าน --permission-mode (เช่น acceptEdits, plan, bypassPermissions)

Quick Win Demo

cd /path/to/your-project
claude -p "explain what this repo does" --max-turns 3

ภายใน 3 turns agent สำรวจ README, package.json, entry point แล้วสรุปโครงสร้างโปรเจกต์กลับมา

❌ ไม่มี tmuxปิด SSH = process ตาย

งานที่ทำค้างไว้หายหมด ต้องเริ่มใหม่

VS
✅ ใช้ tmuxsession อยู่บน server เอง

ปิด SSH ได้ session ยังรันต่อ กลับมา attach ใหม่ได้

tmux พื้นฐานที่ต้องรู้

คำสั่งใช้ทำอะไร
tmux new -s workสร้าง session ใหม่ชื่อ work
Ctrl-b แล้ว dDetach — ออกโดยไม่ปิด process
tmux lsดูรายชื่อ session ทั้งหมด
tmux attach -t workAttach กลับเข้า session
tmux kill-session -t workปิด session ทิ้งถาวร
ข้อควรระวัง: Ctrl-b d = detach (ปลอดภัย) ส่วน exit/Ctrl-d ในเชลล์ = ปิด pane จริง อย่าสับสน — พิมพ์ exit ตอน Claude Code กำลังทำงานจะ kill งานทันที

Workflow จริง: Claude Code ผ่าน tmux

🔑SSH เข้า server
→
🪟tmux new -s claude-work
→
🤖claude (คุยงานตามปกติ)
→
👋Ctrl-b d (detach)
→
🔁ssh + tmux attach -t claude-work
# 1. SSH เข้า server ตามปกติ
ssh user@remote-server

# 2. สร้าง tmux session แล้วรัน Claude Code ข้างใน
tmux new -s claude-work
claude
# ... คุยงานกับ Claude Code ตามปกติ อาจใช้เวลานาน ...

# 3. Ctrl-b แล้ว d (detach) — กลับสู่ shell ปกติ session ยังรันอยู่เบื้องหลัง

# 4. กลับมาดูทีหลัง (แม้ SSH connection เดิมหลุดไปแล้ว)
ssh user@remote-server
tmux attach -t claude-work
# กลับเข้าไปเห็น Claude Code ตรงจุดที่ค้างไว้เป๊ะ

รันหลายงานพร้อมกันด้วยหลาย tmux session

# ตั้งชื่อ session ให้สื่อความหมาย แยกงานตามโปรเจกต์/task
tmux new -s frontend-fix -d    # -d = สร้างแบบ detached ทันที
tmux new -s backend-refactor -d
tmux new -s db-migration -d

tmux ls

# ส่งคำสั่งเข้า session โดยไม่ต้อง attach ก่อน
tmux send-keys -t frontend-fix 'claude -p "fix the failing test in Button.test.tsx"' Enter

# ตรวจความคืบหน้าแบบไม่ต้อง attach เข้าไปเต็มๆ
tmux capture-pane -t frontend-fix -p -S -30

tmux send-keys + capture-pane คือรากฐานเดียวกับที่ Module 07 (Multi-Agent Orchestration) ใช้ spawn หลาย Claude Code instance — ต่างกันแค่ที่นี่คุณสั่งเอง ส่วน Module 07 ให้ agent อื่นสั่งแทน
