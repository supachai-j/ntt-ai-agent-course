Claude Code CLI — Fundamentals

ติดตั้ง Claude Code จริงบนเครื่อง, ยืนยัน auth, สร้างโปรเจกต์ทดลองพร้อม CLAUDE.md แล้วรัน Claude Code ครั้งแรกกับ task จริง — ตรวจผลลัพธ์ด้วย jq ทุก step

⏱ 45-55 นาที 💻 ต้องมี node/npx ในเครื่อง 🌐 ต้องมี Claude Pro/Max subscription หรือ ANTHROPIC_API_KEY 🐚 Bash + jq + tmux

Prerequisites

  • ☐ มี Node.js และ npm ติดตั้งแล้ว (เครื่อง lab นี้มี node/npx พร้อมใช้)
  • ☐ มีสิทธิ์ npm global install (npm install -g) หรือใช้ npx แทนได้
  • ☐ มี Claude.ai account (Pro/Max) สำหรับ OAuth login หรือ มี ANTHROPIC_API_KEY
  • ☐ ติดตั้ง jq สำหรับ parse JSON output (jq --version ตรวจสอบก่อน)
  • ☐ ติดตั้ง git (ใช้ git init สร้างโปรเจกต์ทดลอง)
  • ☐ ติดตั้ง tmux สำหรับ step 9-10 (tmux -V ตรวจสอบก่อน)

Objectives

  • ติดตั้งและ verify การทำงานของ Claude Code CLI บนเครื่องจริง
  • เข้าใจความแตกต่างระหว่าง interactive mode กับ print mode ผ่านการรันจริง
  • เขียน CLAUDE.md ของตัวเองและเห็นผลว่า agent ใช้ context นั้นจริง
  • รัน print mode พร้อม --output-format json แล้ว parse ผลลัพธ์ด้วย jq
  • รัน Claude Code ข้างใน tmux, detach/attach, และรันหลาย session พร้อมกันได้
  • รู้วิธี diagnose ปัญหา auth เบื้องต้นเมื่อ Claude Code ใช้งานไม่ได้

1ติดตั้ง Claude Code

ติดตั้ง CLI แบบ global ผ่าน npm — เครื่อง lab นี้มี node/npx พร้อมใช้งานแล้ว

npm install -g @anthropic-ai/claude-code

ตรวจว่าติดตั้งสำเร็จและ path ถูกต้อง:

claude --version
Verify: output ควรเป็นเลข version เช่น 2.1.281 (Claude Code) และ exit code เป็น 0 (เช็คด้วย echo $?)

2ตรวจสุขภาพการติดตั้งด้วย claude doctor

claude doctor ตรวจ path ของ binary, การตั้งค่า auto-update, และเช็คว่ามีการติดตั้งซ้ำซ้อนหรือไม่

claude doctor
Verify: ต้องเห็นบรรทัด No installation issues found. ใกล้ท้าย output — ถ้าเจอ "Multiple installations found" ให้จดไว้ แต่ยังใช้งานต่อได้ถ้า claude --version ทำงานปกติ

3ยืนยัน Authentication

เลือกวิธี auth วิธีใดวิธีหนึ่ง แล้วยืนยันสถานะ:

# วิธี A: OAuth ผ่าน browser (ต้องมี Claude Pro/Max)
claude
# (รอบแรกจะเปิด browser ให้ login — หลัง login เสร็จกด Ctrl+C ออกจาก REPL ได้)

# วิธี B: login แบบ console สำหรับ API billing
claude auth login --console

# วิธี C: ตั้ง API key ตรงๆ ผ่าน environment variable
export ANTHROPIC_API_KEY="sk-ant-your-key-here"

ไม่ว่าจะเลือกวิธีไหน ให้ตรวจสถานะด้วยคำสั่งนี้:

claude auth status
Verify: output เป็น JSON ที่มี "loggedIn": true เช่น: 
{
  "loggedIn": true,
  "authMethod": "claude.ai",
  "apiProvider": "firstParty",
  "email": "you@example.com"
}
หมายเหตุ: ถ้าตั้งทั้ง OAuth login และ ANTHROPIC_API_KEY พร้อมกัน พฤติกรรมลำดับความสำคัญอาจต่างกันตาม version — ใช้ claude auth status เพื่อดูว่าจริงๆ แล้วกำลังใช้ authMethod ไหนอยู่ (ตรวจสอบ syntax ล่าสุดกับ --help ก่อนใช้งานจริง)

4สร้างโปรเจกต์ทดลอง

สร้าง directory ใหม่ ใส่ git init และไฟล์ตัวอย่างเล็กๆ ให้ Claude Code มีอะไรให้สำรวจ

mkdir -p ~/lab03-claude-code && cd ~/lab03-claude-code
git init
echo "print('hello world')" > app.py
echo "# Lab 03 test project" > README.md
git add -A
git commit -m "init lab project"
Verify: git log --oneline ต้องแสดง commit "init lab project" และ git status ต้องขึ้น working tree clean

5เขียน CLAUDE.md ของตัวเอง

สร้างไฟล์ project memory ที่ Claude Code จะ auto-load ทุกครั้งที่ทำงานใน directory นี้

cat > CLAUDE.md << 'EOF'
# Project: lab03-claude-code

## Architecture
Single-file Python demo project used for Claude Code lab exercises.

## Key commands
- Run: python app.py

## Code standards
- Keep it minimal, this is a lab sandbox
EOF
Verify: cat CLAUDE.md ต้องแสดงเนื้อหาที่เขียนไว้ครบ และ wc -l CLAUDE.md ควรได้ประมาณ 10 บรรทัด

6รัน Claude Code ครั้งแรกด้วย Print Mode

ใช้ -p (print mode) รัน task ง่ายๆ แบบ one-shot ไม่มี interactive dialog — จำกัดจำนวนรอบด้วย --max-turns

claude -p "list all files and explain the project structure" --max-turns 5
Verify: ต้องได้คำอธิบายโครงสร้างโปรเจกต์เป็นข้อความกลับมา (ไม่ใช่ error) และ exit code เป็น 0. Agent ควรพูดถึง app.py, README.md, และ CLAUDE.md ที่สร้างไว้ในขั้นก่อนหน้า — พิสูจน์ว่า agent เห็นและใช้ context จริง

7ตรวจผลลัพธ์แบบ JSON ด้วย jq

รันซ้ำแต่ขอ output เป็น JSON เพื่อดึงข้อมูล metadata เช่น cost และ session ID — ใช้ได้ทั้งสำหรับ debug และ log ใน automation pipeline

claude -p "list all files and explain the project structure" \
  --output-format json --max-turns 5 > claude_output.json

cat claude_output.json | jq -r '.result'
cat claude_output.json | jq -r '.session_id, .total_cost_usd, .num_turns'
Verify: jq -r '.session_id' ต้องได้ UUID (เช่น 447dff69-0c56-4c89-...), .total_cost_usd ต้องเป็นตัวเลขทศนิยมเล็กๆ (เช่น 0.0799...), และ jq empty claude_output.json (ไม่ error) ยืนยันว่าเป็น valid JSON

8ทดลอง Interactive Mode (เปรียบเทียบ)

เปิด REPL แบบ interactive ใน directory เดียวกัน เพื่อเห็นความต่างจาก print mode — จะเจอ trust dialog เพราะเป็น directory ใหม่ที่ยังไม่เคย trust

cd ~/lab03-claude-code
claude
# ตอบ trust dialog แรกที่ขึ้นมา (เลือก "Yes, proceed")
# ลองพิมพ์: "what does this project do?"
# ออกจาก session ด้วย Ctrl+C หรือพิมพ์ /exit
Verify: เห็น trust dialog ก่อนเข้า REPL (ต่างจาก print mode ที่ข้าม dialog นี้), และ agent ตอบคำถามโดยอ้างอิงเนื้อหาจาก CLAUDE.md ที่เขียนไว้
Workspace safety: Trust dialog มีไว้ป้องกันการรันโค้ด/คำสั่งจาก directory ที่ไม่รู้จักที่มาโดยไม่ตั้งใจ — อย่า trust directory ที่ไม่ใช่ของตัวเองหรือไม่ผ่านการตรวจสอบ

9tmux: รัน Claude Code แบบ persistent session

จำลองสถานการณ์ SSH disconnect จริง — สร้าง tmux session, รัน Claude Code ข้างใน, detach ออกมา (โดยที่ process ยังรันอยู่) แล้ว attach กลับเข้าไปดู

# สร้าง tmux session ชื่อ lab03
tmux new -s lab03

# (ตอนนี้อยู่ข้างใน tmux session แล้ว — prompt อาจดูเหมือนเดิมแต่สังเกต status bar ล่างสุดของจอ)
cd ~/lab03-claude-code
claude -p "count the lines of code in app.py and explain what it does" --max-turns 3

รอให้ Claude Code ตอบเสร็จ แล้วลอง detach ออกจาก session โดยไม่ปิด terminal:

# กด Ctrl-b ปล่อยมือ แล้วกด d (สองปุ่มแยกกัน ไม่ใช่กดพร้อมกัน)
# หลัง detach จะกลับมาเห็น shell ปกติ (ไม่ใช่ error, session ยังอยู่)
Verify: รัน tmux ls จาก shell ปกติ (นอก tmux) ต้องเห็นบรรทัด lab03: 1 windows (created ...) ยืนยันว่า session ยังมีชีวิตอยู่แม้ detach ออกมาแล้ว

10Attach กลับเข้า session และรันหลายงานพร้อมกัน

Attach กลับเข้า session เดิมเพื่อดูผลลัพธ์ที่ค้างไว้ — เสมือนไม่เคย detach ออกไปเลย:

tmux attach -t lab03
# ต้องเห็นผลลัพธ์จาก claude -p ที่รันไว้ก่อนหน้าค้างอยู่บนจอ

ลองสร้างอีก session แยกสำหรับงานคู่ขนาน แล้วส่งคำสั่งเข้าไปโดยไม่ต้อง attach ก่อน (ใช้ pattern เดียวกับที่ Module 07 จะสอนต่อ):

# สร้าง session ที่สองแบบ detached ทันที
tmux new -s lab03-second -d

# ส่งคำสั่งเข้า session ที่สองโดยตรงจากภายนอก
tmux send-keys -t lab03-second 'cd ~/lab03-claude-code && claude -p "list all files" --max-turns 2' Enter

# รอสัก 10-15 วินาทีให้ทำงานเสร็จ แล้วดูผลลัพธ์โดยไม่ต้อง attach เต็มรูปแบบ
sleep 15 && tmux capture-pane -t lab03-second -p -S -20
Verify: tmux ls ต้องเห็น 2 session (lab03 และ lab03-second), และ tmux capture-pane ต้องแสดงผลลัพธ์จาก Claude Code จริง ไม่ใช่จอเปล่า

ทำความสะอาดหลังลองเสร็จ — ปิด session ทั้งสองที่สร้างไว้:

tmux kill-session -t lab03
tmux kill-session -t lab03-second
ข้อควรระวัง: tmux kill-session ปิด process ข้างในทันทีไม่มีการเตือน — ถ้า Claude Code กำลังทำงานสำคัญอยู่ (เช่น เขียนไฟล์ครึ่งๆ กลางๆ) ให้รอจนงานเสร็จหรือ detach รอไว้ก่อน อย่า kill session ขณะ agent กำลัง execute อยู่
Troubleshoot: tmux ไม่มีในเครื่อง / attach แล้ว error

ถ้า tmux: command not found:

  • ติดตั้งผ่าน package manager ของระบบ เช่น sudo apt install tmux (Ubuntu/Debian) หรือ brew install tmux (macOS)

ถ้า tmux attach -t lab03 ขึ้น "no sessions" หรือ "can't find session":

  • เช็คชื่อ session ที่ถูกต้องด้วย tmux ls ก่อนเสมอ — พิมพ์ชื่อผิดเป็นสาเหตุที่พบบ่อยที่สุด
  • ถ้า session ถูก kill ไปแล้ว (เช่นเผลอพิมพ์ exit แทน detach) ต้องสร้างใหม่ ไม่มีทางกู้คืน state เดิมได้

ถ้าเผลอพิมพ์ exit ข้างใน tmux แทนที่จะ detach:

  • Session (และ process ข้างใน รวมถึง Claude Code ที่กำลังรัน) จะถูกปิดทันที — นี่คือความต่างสำคัญระหว่าง "detach" (Ctrl-b d, ปลอดภัย) กับ "exit shell" (ปิดถาวร)
  • ป้องกันไว้ก่อน: ฝึกกด Ctrl-b d ให้เป็นนิสัยทุกครั้งที่จะออกจาก tmux ไม่ใช่พิมพ์ exit
Troubleshoot: Auth ล้มเหลว / ANTHROPIC_API_KEY ไม่ถูกอ่าน

อาการ: claude -p "..." ค้างหรือ error เกี่ยวกับ authentication

  1. เช็คสถานะปัจจุบันก่อน: claude auth status — ดูว่า loggedIn เป็น true ไหม และ authMethod คืออะไร
  2. ถ้าตั้งใจใช้ API key แต่ auth status ไม่แสดง ให้เช็คว่า env var ถูก export จริง: 
    echo $ANTHROPIC_API_KEY | head -c 10
    (ควรเห็นตัวอักษรบางส่วนของ key ไม่ใช่บรรทัดว่าง)
  3. ถ้าใช้ OAuth แต่ browser ไม่เปิดอัตโนมัติ (เช่น รันบน remote/headless server) ให้ลอง claude auth login --console แทน ซึ่งจะให้ copy ลิงก์ไปเปิดเองในเครื่องอื่น
  4. Logout แล้ว login ใหม่ถ้าสถานะดู corrupt: claude auth logout ตามด้วย claude auth login
  5. ยืนยันด้วย claude doctor อีกครั้งว่าไม่มี installation issue ที่กระทบ auth

(ตรวจสอบ syntax ล่าสุดกับ claude auth --help ก่อนใช้งานจริง เพราะ flag อาจเปลี่ยนตาม version)

สรุป & ต่อยอด

ตอนนี้ควรมี Claude Code ติดตั้งและ auth เรียบร้อยบนเครื่อง, เข้าใจความต่างระหว่าง interactive กับ print mode จากการรันจริง, เห็นแล้วว่า CLAUDE.md มีผลต่อคำตอบของ agent จริง, รู้วิธีดึง metadata (cost, session id) จาก JSON output ด้วย jq, และรัน Claude Code ผ่าน tmux แบบที่รอดจาก SSH disconnect ได้จริง

  • ลองปรับ CLAUDE.md ให้ละเอียดขึ้น (เพิ่ม code standards, key commands) แล้วดูว่าคำตอบของ agent เปลี่ยนไปอย่างไร
  • ลอง --allowedTools จำกัด tool ที่ agent ใช้ได้ในโปรเจกต์ทดลองนี้
  • ลอง -c/--continue เพื่อสานต่อบทสนทนาเดิมแทนที่จะเริ่มใหม่ทุกครั้ง
  • ลองตั้งชื่อ tmux session ให้เป็นระบบ (เช่น project-task) เมื่อทำงานหลายโปรเจกต์พร้อมกันจริง
  • Module ถัดไป (04) จะพาไปลึกขึ้น: feature dev loop, PR review, TDD กับ Claude Code
