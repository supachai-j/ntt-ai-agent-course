Hooks, Permissions & MCP Integration

การควบคุม agent อย่างปลอดภัย และเชื่อมต่อกับระบบภายนอกจริง

ทำไมต้องคุม Claude Code

Agent ที่รัน tool ได้เองมีพลังมาก แต่ก็เสี่ยงมาก

🔑 Permissions — tool ไหนใช้ได้/ห้าม/ต้องถาม
🪝 Hooks — script ที่ block ได้จริง (deterministic)
🔌 MCP — มาตรฐานต่อ tool/data ภายนอก

Permission Modes

Modeพฤติกรรม
defaultถามยืนยันทุก tool call ที่มีผลกระทบ
acceptEditsยอมรับ file edit อัตโนมัติ แต่ยังถาม bash
planวางแผนอย่างเดียว ห้าม execute
bypassPermissionsข้ามทั้งหมด — เฉพาะ sandbox/CI

เลือกผ่าน --permission-mode หรือ Shift+Tab

--allowedTools / --disallowedTools

# อนุญาตเฉพาะ Bash และ Read เท่านั้น ที่เหลือถามก่อนเสมอ
claude -p "run the test suite" --allowedTools "Bash,Read"

# ห้ามใช้ WebFetch โดยเด็ดขาด
claude --disallowedTools "WebFetch" -p "review this PR"

# allow เจาะจงถึงระดับ command pattern
claude --allowedTools "Bash(git diff:*)" "Bash(git log:*)"
✅ Tool(pattern:*) ให้ควบคุมละเอียดกว่า allow ทั้ง tool

สูง → ต่ำ: scope แคบกว่า merge ทับ scope กว้างกว่า

ตัวอย่าง permissions ใน settings.json

{
  "permissions": {
    "allow": [
      "Bash(git diff:*)",
      "Bash(git status)",
      "Read(*)"
    ],
    "ask": [
      "Bash(git push:*)",
      "Edit(*)"
    ],
    "deny": [
      "Read(.env)",
      "Read(**/*.pem)",
      "Bash(rm -rf *)"
    ]
  }
}
⚠️ deny ชนะทุกกรณี — override ไม่ได้แม้ user จะ allow เองใน local

PreToolUse: Security Gate ตัวจริง

code ที่รันจริง — ต่างจาก permission ask/deny (config ปกติ)

📄{tool_name, tool_input}stdin
→
🔍check
✅exit 0allow, tool รันต่อ
VS
⛔exit 2block, stderr → agent เห็นเหตุผล

exit code อื่น → error, non-blocking แต่ log ไว้

ตัวอย่าง Hook: บล็อก rm -rf / force push

#!/usr/bin/env bash
# .claude/hooks/guard-bash.sh
input=$(cat)
tool_name=$(echo "$input" | jq -r '.tool_name')
command=$(echo "$input" | jq -r '.tool_input.command // empty')

[ "$tool_name" != "Bash" ] && exit 0

if echo "$command" | grep -Eiq 'rm[[:space:]]+-rf[[:space:]]+(/|\*|~)'; then
  echo "BLOCKED: destructive rm -rf detected: $command" >&2
  exit 2
fi

if echo "$command" | grep -Eiq 'git[[:space:]]+push[[:space:]].*--force'; then
  echo "BLOCKED: force push not allowed by policy" >&2
  exit 2
fi

exit 0

ผูก Hook เข้ากับ settings.json

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/guard-bash.sh"
          }
        ]
      }
    ]
  }
}

matcher กรองว่า hook ทำงานกับ tool ไหน — ที่นี่เฉพาะ Bash

MCP คืออะไร

Model Context Protocol — มาตรฐานเปิดต่อ agent เข้ากับ external tool/data source โดยไม่ต้องเขียน integration เฉพาะทุกครั้ง

📟 stdiosubprocess local
🌐 httpremote request/response
📡 ssestreaming events

MCP server ประกาศ tools / resources / prompts — Claude Code discover แล้วต่อเข้า tool list

เพิ่ม MCP Server จริง

# stdio server (subprocess) — postgres MCP
claude mcp add postgres -s project -- npx -y @modelcontextprotocol/server-postgres \
  "postgresql://user:***@localhost/db"

# HTTP/remote server — GitHub MCP
claude mcp add --transport http github https://api.githubcopilot.com/mcp \
  --header "Authorization: Bearer ***"

# ตรวจสอบว่าติดตั้งและเชื่อมต่อสำเร็จ
claude mcp list
claude mcp get postgres

Scope: -s user / -s project (.mcp.json แชร์ทีม) / -s local

MCP Resource Reference

# ใช้ MCP resource ตรงๆ ใน chat ด้วย URI scheme <server-name>:<resource-path>
คุณ: สรุป @github:issue://123 ให้หน่อย แล้วเสนอ fix
🔗 @server:type://id ดึงข้อมูล live จาก external system เข้ามาเป็น context ได้ทันที

MCP ใน CI / Bare Mode
