Module 07 · Scale

Multi-Agent Orchestration

Subagents · Parallel Delegation · Verify Before Trust

เมื่อไหร่ต้องใช้ Multi-Agent

Single agent พอ

  • งาน sequential เดียว context เล็ก
  • งานที่ต้อง maintain state ต่อเนื่อง
  • Debug/fix เฉพาะจุดในไฟล์เดียว

ต้องแตกเป็น Multi-Agent

  • Context ใหญ่เกินจะยัดใน context window เดียว
  • งาน independent ที่รันขนานได้ (parallelizable)
  • ต้องการ specialist role แยก — security reviewer, test writer, docs writer

สามสัญญาณหลักที่บอกว่าถึงเวลาแตก Agent

1 Context overflow — งานมีไฟล์/สเปกเยอะจนโมเดลลืม instruction ต้นๆ หรือ performance ตกเมื่อ context ยาว

2 Parallelizable independent tasks — งาน A ไม่ต้องรอผล B เช่น เขียน README กับเขียน test คนละไฟล์ ไม่ share state

3 Role specialization — อยากได้ persona/system prompt ที่ focus แคบ เช่น "review เฉพาะ security" แทนที่จะให้ agent ตัวเดียวสวมหลายหมวก

Claude Code Custom Subagents

สร้าง subagent เป็นไฟล์ Markdown ที่มี YAML frontmatter ใน .claude/agents/*.md

---
name: reviewer
description: Reviews code for security issues, bad practices, and style violations. Use proactively after writing or editing code.
model: sonnet
tools: Read, Grep, Glob
---

You are a senior security-focused code reviewer.
Review the diff or files given for:
- Injection risks (SQL, command, template)
- Secrets/credentials committed in plaintext
- Missing input validation
- Unsafe deserialization

Report findings as a list with severity (critical/high/medium/low),
file:line reference, and a concrete fix suggestion. Do not modify files.

เรียกใช้ Subagent

Static agent (ไฟล์ .md)

› @reviewer check this diff for security issues

Claude Code จะโหลด system prompt + tools ที่ระบุใน frontmatter แล้วรันเป็น subagent แยก context

Dynamic agent (CLI flag)

claude -p "review auth.py" \
  --agents '{"reviewer":{"description":"security reviewer","prompt":"You are a security reviewer...","tools":["Read","Grep"]}}'

กำหนด agent ชั่วคราวตอนรัน CLI โดยไม่ต้องสร้างไฟล์ — เหมาะกับ automation/CI

Subagent Frontmatter Fields

Fieldความหมาย
nameชื่อที่ใช้เรียกด้วย @name
descriptionบอก Claude Code ว่า agent นี้ทำอะไร ใช้ตอนไหน (auto-delegation)
modelโมเดลที่ subagent นี้ใช้ (เช่น sonnet, opus) — เลือกให้เหมาะกับงาน/cost
toolsจำกัด tool ที่ subagent เข้าถึงได้ — ตัด write access ถ้าไม่ต้องใช้

Parallel Claude Instances ผ่าน tmux

รันหลาย independent task พร้อมกัน — แต่ละ task แยก tmux session ของตัวเอง

# สร้าง session แยกสำหรับแต่ละงาน
tmux new-session -d -s task-readme "claude -p 'write README.md for this repo' > out-readme.log"
tmux new-session -d -s task-tests  "claude -p 'write unit tests for utils.py' > out-tests.log"

# monitor ผลแบบ loop
for s in task-readme task-tests; do
  echo "=== $s ==="
  tmux capture-pane -t "$s" -p | tail -20
done

# เช็คว่า session จบหรือยัง แล้ว kill session ที่ค้าง
tmux list-sessions
tmux kill-session -t task-readme

Anti-pattern: Dependency Race Condition

❌ อย่าทำ

รัน "เขียน API endpoint" กับ "เขียน integration test ที่เรียก endpoint นั้น" แบบขนานกัน — task B อาจ generate test ก่อน task A สร้าง endpoint จริง ผลคือ test อ้าง signature ที่ยังไม่มี หรือ mock ผิดจากของจริง

✅ ทำแบบนี้

งานที่มี dependency ต้องรัน sequential (A เสร็จก่อนจึงเริ่ม B) หรือให้ agent เดียวทำทั้งคู่เพื่อรักษา context ต่อเนื่อง เฉพาะงานที่ independent จริง (ไม่ share state/interface) ถึงรันขนานได้

Hermes delegate_task Pattern

หลักการเดียวกับ Claude Code subagents — เทียบจาก Module 02:

  • Isolated context — subagent ไม่เห็น conversation history ของ parent agent
  • ต้องส่ง context ที่จำเป็นทั้งหมด — path, spec, constraint ต้องระบุชัดใน task prompt เพราะ subagent ไม่ได้ "จำ" อะไรมาก่อน
  • ผลลัพธ์เป็น self-report — subagent สรุปว่า "ทำสำเร็จ" แต่นั่นคือคำบอกเล่า ไม่ใช่หลักฐาน

หลักการร่วม: Verify ก่อนเชื่อ

ไม่ว่าจะเป็น Claude Code subagent หรือ Hermes subagent — parent agent ต้องตรวจ evidence จริง (ไฟล์ที่มีอยู่จริง, test ที่รันผ่านจริง, output ที่ diff ได้) ก่อนถือว่างานเสร็จ

ทำไมต้อง Verify เสมอ

พฤติกรรมเสี่ยงทำไมอันตราย
เชื่อ log "Done" จาก subagent ทันทีSubagent อาจ hallucinate ว่าทำสำเร็จ ทั้งที่ error หรือไฟล์ไม่ถูกสร้าง
ไม่เปิดไฟล์ output จริงเนื้อหาอาจไม่ตรงสเปก หรือ syntax ผิดที่ log ไม่ได้บอก
ไม่รัน test/lint หลัง subagent เสร็จCode compile ไม่ผ่าน แต่ subagent รายงานว่าเขียนเสร็จแล้ว

Agent Teams (Advanced)

Claude Code รองรับโหมด multi-agent แบบ collaborative ผ่าน flag ระดับ advanced:

claude --teammate-mode --brief "coordinate with other agents on this refactor"
  • --teammate-mode — เปิดโหมดให้ agent ทำงานร่วมกันเป็นทีม แชร์สถานะระหว่างกัน
  • --brief — ข้อความสั้นสำหรับ SendUserMessage ที่ agent อื่นในทีมเห็นได้

เป็น feature ขั้นสูง เหมาะกับ workflow ที่ต้องประสาน agent หลายตัวจริงๆ — เริ่มจาก subagent เดี่ยว + parallel tmux ให้คล่องก่อน
