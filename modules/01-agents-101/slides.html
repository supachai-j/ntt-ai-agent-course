LLM call ธรรมดา คืออะไร

Single-turn inference

ส่ง prompt เข้าไป → โมเดลตอบกลับมาครั้งเดียว → จบ

User: "สรุป email นี้ให้หน่อย"
LLM:  [สรุปข้อความ] → จบการทำงาน

โมเดลไม่รู้จักโลกภายนอก ไม่สามารถไปอ่านไฟล์ เรียก API หรือรันคำสั่งเองได้

Agent คืออะไร

สิ่งที่ทำให้เป็น agent ไม่ใช่โมเดลที่ฉลาดกว่า แต่คือ agentic loop

Agentic Loop

1 Observe (ดู state / user request)
2 Plan (ตัดสินใจว่าต้องทำอะไรต่อ)
3 Act (เรียก tool / function call)
4 Observe result (ดูผลลัพธ์จาก tool)
→ วนกลับไปข้อ 1 จนงานเสร็จ หรือถึง limit

Agentic Loop ในทางปฏิบัติ

User: "เช็คว่า service X down อยู่ไหม แล้ว restart ถ้า down"

Loop:
  observe → user request
  plan    → ต้องเรียก tool "check_status" ก่อน
  act     → check_status("service-x")
  observe → result: "down"
  plan    → ต้องเรียก tool "restart_service"
  act     → restart_service("service-x")
  observe → result: "restarted, status: up"
  plan    → งานเสร็จแล้ว ไม่ต้องเรียก tool เพิ่ม
  → ตอบ user: "restart สำเร็จ service กลับมา up แล้ว"

องค์ประกอบหลักของ agent

  • System prompt / instructions — กำหนดบทบาท ขอบเขต และกติกาการทำงาน
  • Available tools — function calling: อ่าน/เขียนไฟล์, เรียก API, รัน command
  • Memory / context — conversation history, retrieved docs, state ระหว่าง loop
  • Loop controller — ตัดสินใจว่าจะเรียก tool ไหนต่อ หรือหยุดแล้วตอบ user

Chatbot ธรรมดา vs Agent

Chatbot ธรรมดาAgent
Single-turn — ตอบครั้งเดียวจบMulti-turn tool use — วน loop จนงานเสร็จ
ไม่มี tool / ไม่แตะโลกภายนอกเรียก tool จริง: ไฟล์, API, terminal, DB
ผู้ใช้ต้องทำ step ต่อไปเองทำงานหลายขั้นตอนอัตโนมัติ
ไม่มี state ระหว่าง turnเก็บ context/observe result เพื่อวางแผนต่อ
เหมาะกับ Q&A, สรุปข้อความเหมาะกับงานที่ต้องลงมือทำจริง

ทำไม NTT ต้องสนใจ

Presale

research คู่แข่ง/ลูกค้า, drafting proposal เบื้องต้น, สรุป requirement จาก meeting notes ให้เร็วขึ้น

Engineering

เขียนโค้ด, debug, review PR, deploy อัตโนมัติ, ลด manual toil ในงาน routine เช่น log analysis, config check

ตัวอย่างงานจริงที่ agent ช่วยได้

  • Engineer: "หา bug ที่ทำให้ test นี้ fail แล้ว fix ให้" — agent อ่านโค้ด, รัน test, แก้, รันซ้ำ
  • Presale: "สรุป pain point ลูกค้าจาก transcript นี้ แล้วร่าง outline proposal" — agent ค้น, สรุป, ร่าง draft
  • Ops: "ตรวจ log 24 ชม.ที่ผ่านมา หา anomaly แล้วสรุปเป็น report" — agent วน query + สรุปอัตโนมัติ

จุดร่วม: งานที่มีหลายขั้นตอน ทำซ้ำได้ แต่ยังต้องใช้ "การตัดสินใจ" ระหว่างทาง

ความเสี่ยง/ข้อจำกัดที่ต้องรู้

  • Hallucination — agent อาจสร้างข้อมูล/ผลลัพธ์ที่ดูสมเหตุสมผลแต่ผิด
  • สิทธิ์ tool กว้างเกินไป — ให้ agent เข้าถึง production DB หรือ deploy key โดยไม่จำเป็น
  • ต้องมี human-in-the-loop สำหรับ action ที่ irreversible เช่น deploy, delete, ส่งอีเมลลูกค้า

Landscape เครื่องมือที่คอร์สนี้สอน

Hermes

Agent orchestration platform — จัดการ profile, skills, memory, MCP tool layer และ connector (Discord/Telegram/Email) ให้ agent ทำงานแบบ persistent, multi-channel

Claude Code

Coding agent CLI — รันในเครื่อง/CI, เข้าถึง filesystem และ terminal โดยตรง เหมาะกับงาน engineering: เขียนโค้ด, review, refactor, automation

ใช้คนละบริบท: Hermes = platform ที่ orchestrate agent หลายตัว/หลาย channel, Claude Code = agent เดี่ยวที่โฟกัสงานโค้ดในเครื่อง — Module 02 และ 03 จะลงลึกแต่ละตัว

สรุป

  • Agent = LLM + agentic loop (observe → plan → act → observe) + tools + memory
  • ต่างจาก chatbot ตรงที่ทำงานหลายขั้นตอนอัตโนมัติผ่าน tool call จริง
  • มีประโยชน์ชัดเจนทั้งฝั่ง presale และ engineering แต่ต้องระวัง hallucination และสิทธิ์ tool
  • Action ที่ irreversible ต้องมี human-in-the-loop เสมอ
